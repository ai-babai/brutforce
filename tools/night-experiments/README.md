## Данные и порядок действий

1. Скачать публичную неизменную v2; проверить все image SHA и suite hash.
2. Сопоставить case ID / track / SHA с исходными ответами B. Совпадение названий недостаточно.
3. Проверить каталог: 2103 слота, 2060 доступных по gate-v2. Не возвращать 20 исключённых изображений.
4. Передавать на inference GPU только изображения, открытые поля каталога, предыдущие ответы и код.
5. После сохранения raw predictions считать качество на доверенном компьютере/сервере.
6. Не менять v2/gold и не исключать неудобные кейсы. Новые результаты — новые submissions.

## Qwen VL Reranker 2B

```text
B: выбранная цель → область этикетки + Top20
  → пара «кроп запроса, эталон кандидата + открытые поля каталога»
  → готовый Qwen3-VL-Reranker-2B → оценка пары
  → Top20 / перестановка первых 5 / RRF / осторожная перестановка
```

Модель: `Qwen/Qwen3-VL-Reranker-2B`,
revision `4bd860ac4f15ad1897a214615cccc700f8f71818`.
Официальный код [Qwen3-VL-Embedding](https://github.com/QwenLM/Qwen3-VL-Embedding),
commit `393e2978d27852b0d0230d6994f37f9c15bed73c`.
Он хранится отдельным checkout вне Git проекта. `qwen_rerank.py` импортирует его класс.

`prepare.py` не загружает gold. Он проверяет SHA, применяет EXIF-поворот,
вырезает область, реально выбранную B, и сохраняет PNG без потерь.
Никакие ожидаемые названия не передаются в модель.
Если B не сформировал кандидатов, дополнительный этап этого не исправляет.
Для OCR-кандидатов без разрешённого эталона остаются текстовые поля; подмена фото запрещена.

Перед полным прогоном проверяются batch-1 и выбранный microbatch на тех же парах.
При расхождении более 0.005 используется batch-1. Это инженерный контроль, не проверка по gold.
На RTX3090 исходная Conv3d-проекция одного патча занимала 15.55 с из 16.06 с пары.
Флаг `--linear-patch` заменяет её эквивалентным по алгебре F.linear с теми же весами:
kernel=stride, padding=0, groups=1, каждый вход уже отдельный патч.
BF16-проверка: relative L2 0.00169, max abs 0.015625; это не побитовая эквивалентность.
Скорость пары после замены около 0.08 с; окончательное качество измеряется для этой реализации.
Microbatch4 менял порядок близких оценок; полный опыт использует batch1.

Ошибка чтения изображения не заменяется молча строкой NULL; она фиксируется явно.
Предел контекста проверяется без усечения токенов изображения.

`export_rerank.py` требует полный набор 316 ответов и неизменный пул каждого запроса.
Четыре варианта сохраняются раздельно; подбор по этим же корзинам — исследовательский,
не независимая оценка обобщения. Вариант с порогом 0.8/отрывом 0.2 не является OOD-калибровкой.
При ошибке дополнительного этапа остаётся B, а причина fallback сохраняется.

Время в offline-submission — **только измеренный дополнительный этап**.
Оно не складывается незаметно с историческим временем B. Полный HTTP SLA требует свежего
запуска всех компонентов, загрузки фото и ограничения 10 секунд на том же оборудовании.

Скореры [CPU](../night-cpu/) проверяют полноту ID, версию, hash и знаменатели:
151 service (141 graded), 62 retrieval; 103 organizer-файла → 100 уникальных фото.

Публикуется только сводка и разрешённые результаты проверки. Полные raw, приватные метки

токен берётся из `/srv/lct/eval-access/participant.env` без вывода в логи.
После выгрузки артефактов и проверки SHA временные pod удаляются. TEST/PROD не заменяются.

## Дополнительные проверки

`homoglyph_ablation.py`: одинаковое для всех запросов исправление визуально похожих
латинских букв в токенах, уже содержащих кириллицу. Чисто латинские слова и цифры
не меняются. Поиск снова выполняется по полному каталогу, затем используется прежний RRF.
Если текст не изменился, порядок результатов должен точно совпасть с B.

`export_so400m_onnx.py`: только визуальная башня SO400M FP32, вход batch1 384×384,
ONNX opset17. 16 реальных входных кропов: максимальное расхождение нормализованного
вектора около 1e-6, cosine около1. Это проверка экспорта, не гарантия одинакового
Top1 возле ничьей. CPU Sigma должен пройти отдельный замер с тем же индексом.
Измерения на процессоре GPU-пода не переносятся на Sigma.

`score_qwen.py` запускается только на доверенном хосте после полного inference.
`build_report.py` читает агрегированные метрики; не публикует индивидуальные правильные ответы.

## Карточки и интерпретация ошибок

- `grape_evidence_ablation.py`: один буквальный сорт в OCR, полностью разобранное
  поле grapes; стабильное опускание противоречащих кандидатов, без удаления из Top20.
  Не доказательство правильного SKU и не механизм отказа. Полный отрицательный опыт сохранён.
- `enrich_website_cards.py`: дополнительная категория/сладость из ранее сохранённого
  публичного сайта. Только прямой slug с совпадением названия/производителя; ни alias,
  ни query gold. 2029 дополненных карточек,69 отсутствующих и5 конфликтных оставлены пустыми.
  Отдельная версия входа; исходный CSV и эталоны не заменяются.
- `organizer_error_audit.py`: только доверенный evaluator. Файл содержит правильные
  ответы и доказательства, хранится вне Git/web-root. Пять известных reference-конфликтов
  показаны дополнительным срезом, но не выброшены из основного знаменателя54.
- Свежий HTTP Qwen: [night-qwen-http](../night-qwen-http/). Uncapped, строгий deadline
  и ретроспективная проекция — три разных типа свидетельств, не взаимозаменяемые прогоны.
