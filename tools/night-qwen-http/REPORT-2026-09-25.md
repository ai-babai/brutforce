# Fresh B → Qwen3-VL-Reranker-2B HTTP validation

## Architecture

```text
original image bytes
    │
    ▼
B service (RT-DETR target, OWLv2 label, PaddleOCR, SigLIP2 retrieval)
    │  current target/label boxes + fixed Top20 candidates
    ▼
Qwen3-VL-Reranker-2B (target crop × each candidate card/reference photo)
    │  score and reorder the same Top20; preserve B no-match action
    ▼
service slug/action or retrieval Top20
```

The two local HTTP processes run on one RTX 3090. Every request sends the
original image bytes and recomputes B; neither endpoint receives a cached B
answer, case label, query gold, or organizer annotation. The first profile uses
the same candidate pool and cards as the earlier offline Qwen experiment.

## First full HTTP baseline

| Capture | Frozen service | Retrieval Top1 / Top5 | Organizer exact Top1 | Deadline result |
|---|---:|---:|---:|---|
| Fresh B + Qwen Top20, uncapped diagnostic | 115/141 | 61/62 · 62/62 | 50/54 | 27 of 316 responses exceeded 10 s |
| Fresh B + Qwen Top20, actual curl 10 s | 110/141 | 61/62 · 62/62 | 47/54 | 9 of 316 requests timed out (5 frozen, 4 organizer) |
| Fresh B OMP1/offline + Qwen Top20, actual curl 10 s | 110/141 | 61/62 · 62/62 | 38/54 | 27 of 316 requests timed out (5 frozen, 22 organizer) |
| Fresh B + Qwen Top20 + public website fields, actual curl 10 s | 111/141 | 61/62 · 62/62 | 33/54 | 39 of 316 requests timed out (5 frozen, 34 organizer) |

The uncapped run used a 180-second client read timeout and is a quality
diagnostic, not a deployable 10-second service score. Its retrospective
late-as-error projection produced 110/141 service, 61/62 retrieval, and
37/54 organizer exact Top1; this projection was **not** submitted as an
independent model. The separate actual 10-second run had only four organizer
timeouts rather than the 22 organizer responses over 10 seconds in the
uncapped capture. This shows substantial runtime variability; its cause is
not established. All 307 timely actual strict predictions matched the
uncapped run, so the strict quality difference is deadline handling rather
than a changed reranker decision.

The actual strict capture contains all 316 rows, SHA
`cb4744ca978232c997a8d1f90c61ba43d8698936e7881cc7886869dae5f418b5`.
The client uses curl `--max-time 10` and waits for the single-threaded Qwen
server to finish abandoned work before sending the next image. It records
timeouts rather than silently accepting late HTTP 200 responses.

## Runtime and exploratory profiles

The first B server had 355 OS threads with no `OMP_NUM_THREADS` setting.
Restarting the same B code/checkpoint/index/catalog with `OMP_NUM_THREADS=1`
reduced this to 35 threads. This launch also set `HF_HUB_OFFLINE=1` and
`TRANSFORMERS_OFFLINE=1`; it is therefore a runtime configuration comparison,
not a pure thread ablation. A ten-image smoke test matched the B action and
ordered Top20 exactly on all ten images. The full 316-image strict capture
showed no frozen quality gain and a worse organizer deadline result (22 vs
four timeouts). On all 289 images answered by both strict captures, B ordered
Top20, Qwen rankings, and predictions matched exactly. The original strict
runtime answered 18 additional images; OMP1/offline answered none exclusively.
The common organizer client median rose from 6.12 s to 6.80 s. Since the
capture was repeated serially on the same host, the measured configuration is
unfavorable, but the difference cannot be assigned solely to OMP threads.

An additional exploratory profile adds only verified public website fields
`website_category_and_sweetness` and `website_sweetness` to 2029 matching
catalog cards. The remaining 69 unmatched and five identity-conflict slugs
retain their original descriptions. The website card SHA is
`1520355a0ef1f24788cd4ba5fe91f566d7c6d214927349765ac51f95482d2ebd`.
This profile has separate code, runtime receipt, capture, and submission.
The website strict raw SHA is
`41d879827e1bb3b39fd919c90d7a3cd229af030925e95944279b989ef45b1650`.
On 39 unique exact organizer images with timely HTTP 200 in both baseline and
website captures, website metadata fixed none and broke two Top1 answers.
The trusted scorer uses the first occurrence of each query SHA for its unique
image metric; the website run had three repeated-SHA outcome disagreements
because a repeated request could time out while its mate returned.

The original organizer `participant_test.sh` was also run on six fixed public
images through an SSH tunnel and the multipart-to-single-slug adapter. Five
returned non-null slugs within ten seconds; one returned null after curl timed
out at 10.004 s. The adapter later logged HTTP 200 for all six, which does not
override the participant script's deadline result. This is a six-image wire
contract smoke, not a quality estimate.

## Practical limits

- B OCR dominates the variable B stage on difficult labels; Qwen adds a
  second visual model pass over 20 candidate references.
- The fixed B Top20 is a recall ceiling. Qwen can reorder an existing
  candidate but cannot rescue a missing catalog item or an incorrect target.
- Measured strict results are from one RTX 3090 pod and serial request order.
  They show deadline behavior for that runtime, not a hardware-independent
  latency guarantee.

Raw captures, runtime receipts, exact package lists, scorer outputs, and
submissions are in the sibling `night-20260925/qwen-http` artifact directory.
