# Target-only Qwen3-VL reader: full N2 ablation

**Result:** replacing B's PaddleOCR text with target-only Qwen3-VL-2B transcription in the same fixed rank fusion raised frozen service from 114/141 to **119/141** and retrieval Top1 from 57/62 to **61/62**. Organizer exact Top1 moved from 44/54 to **45/54** unique images. Pure text retrieval was substantially worse. Reader-only L4 latency was p50 **6.73 s**, p95 **9.88 s**, and 11/288 crop calls exceeded 10 s; total B+reader HTTP latency was not measured. The cheaper mixed-script Paddle normalization comparator reached 46/54 organizer exact Top1, so this reader is not the recommended primary path.

## Architecture

```text
raw query → frozen B selection → B label-context crop → Qwen3-VL-2B-Instruct
                                                        │ visible text only
                                                        ▼
                            catalog-wide character-gram OCR rank (Top20)
                                                        │
              B whole-image rank ────────────────────────┤
              B label rank ───────────────────────────────┤ fixed B RRF weights
                                                        ▼
                                              fused Top20 / service action
```

The model prompt contains only the query crop and a fixed instruction to transcribe visible label text line by line or return `<EMPTY>`. It contains no candidate names, catalog, slugs, or answers. The lexical index and fixed 0.25/0.35/0.40 whole/label/OCR RRF weights are the B implementation. Reader text can introduce candidates outside B's original Top20. No training or case-specific gates were used.

## Provenance and controls

- Official [Qwen/Qwen3-VL-2B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct), Apache-2.0, exact revision `89644892e4d85e24eaac8bacfd4f463576704203`.
- Greedy decoding, 128 new tokens maximum, image longest edge 768 pixels, BF16/SDPA. Final prompt SHA-256 `fa0ef7ea4e3d8357849da6f4c5b4be4f2d205c2bddd54afd19b8dde5a52a0e1a`.
- The initial ten-case engineering sample was selected from manifest order without labels. A first prompt sometimes elicited an instruction echo; the final `<EMPTY>` prompt was frozen after this unscored sample, before full inference.
- All 316 rows were generated before private scoring. Full raw SHA-256 `b49c86ab701831adb604f4358a3be07307389bbb418cd618d49ec33473d4e3e3`. 288 crops generated text; 28 B no-target cases required no model call. Zero inference errors; four outputs hit the 128-token cap. All 316 IDs, tracks, dataset tags, and query image SHAs match the slim public input manifest. Reconstructing the original PaddleOCR branch from the catalog had zero Top20 mismatches across 316 cases.
- Qwen reads the B label-context crop; the original PaddleB OCR reads B's selected target JPEG, so the comparison changes OCR model and input view together. The B whole/label visual branches and retrieval catalog remain fixed.
- Scoring used the trusted local frozen-v2 and corrected organizer scorers after inference, with no gold sent to the pod. Organizer numbers use 100 unique SHA and the 54 exact-labeled subset; 42 unresolved, three ambiguous, and one out-of-catalog image are not counted as exact Top1. This is same-suite exploratory evidence, not an independent test set.

## Full results

| Variant | Frozen service correct / 141 | Frozen retrieval Top1 / 62 | Retrieval Top5 / 62 | Retrieval Top20 / 62 | Organizer exact Top1 / 54 | Organizer Top5 / 54 | Organizer Top20 / 54 |
|---|---:|---:|---:|---:|---:|---:|---:|
| B with PaddleOCR | 114 | 57 | 59 | 62 | 44 | 51 | 53 |
| Reader text only | 96 | 41 | 52 | 60 | 36 | 48 | 48 |
| B whole + label + reader text | **119** | **61** | **61** | **62** | **45** | **51** | **53** |

The fused reader fixed six and broke one graded frozen service case; fixed four and broke none in frozen retrieval; and fixed six and broke five organizer exact images versus B. Its fused Top1 changed on 44/316 requests. Reader text was nonempty on 276 requests versus 270 PaddleB OCR texts; its standalone OCR Top1 fell outside B's original Top20 on 58 requests. Cleaner transcripts can help, but generic label text can rank a wrong SKU, and the organizer improvement is only one net image.

## Measured cost and limitations

L4 reader-only timings over 288 crop calls: p50 6,732.923 ms; p95 9,884.999 ms; p99 10,570.298 ms; max 11,288.303 ms; 11 calls over 10 s. Warm model load was about 3.9 s and is excluded. Exports intentionally put **reader-only measured time** in `latency_ms` and name the scope in the solution title; they do not claim complete HTTP SLA. The no-target rows have zero reader time. These costs are high compared with the small organizer improvement and the cheap normalization baseline, so no reader optimization or deployment recommendation follows from this ablation.
