Как устроены решения

B · исходный GPU-поиск

полное фото
  → RT-DETR: бутылки
  → SigLIP Base: центральное вино
  → OWLv2: область этикетки
  ├─ SO400M: целая цель → кандидаты
  ├─ SO400M: этикетка   → кандидаты
  └─ PaddleOCR → текстовый поиск
  → объединение рангов → Top20

Для retrieval-корзин на входе уже проверенный кроп. Каталог обработан заранее. B — контроль для дополнительных этапов на GPU, а не новый результат этой ночи.

CPU · сокращённый поиск

фото → RT-DETR → центральное вино
  ├─ бутылка есть → кроп цели
  └─ бутылки нет → поиск этикетки
       ↓
  SO400M или Base224 → один вектор
       ↓
  сравнение с каталогом → Top20

отдельно: OCR и сочетание ветвей

Каждый вариант измеряется отдельно. Изменение размера OWLv2 может изменить найденную область; это проверка качества и скорости, а не гарантированно эквивалентная оптимизация.

DISK + LightGlue · совпадение деталей

B: выбранная этикетка + Top20
  → DISK: характерные точки
  → LightGlue: пары точек
  → геометрическая проверка
  → новый порядок кандидатов

контроли:
геометрия / смесь / осторожный каскад

Например, совпали буквы, эмблема и рисунок в согласованном расположении. Много совпадений ещё не доказывает точный товар: у разных вин могут повторяться оформление и каталожная фотография.

Qwen VL Reranker 2B · сравнение пары

B: выбранная этикетка + Top20
  → для каждого кандидата:
    фото запроса + фото эталона
    + название и поля каталога
  → Qwen: оценка соответствия
  → новый порядок кандидатов

Это проверка готового списка. Она не вернёт товар, которого нет в Top20, и не исправит неверно выбранную бутылку. Число модели не трактуется как откалиброванная вероятность точного совпадения.

Roman-5 / Roman-20 · выбор кандидата

полное фото + кандидаты B
  ├─ первые 5 → Qwen3.5-4B → выбор
  └─ группы из Top20
       → промежуточные выборы
       → финальные 5 → выбор
  → исходный порог + смесь с B

контроль: base / base + адаптер Ромы

Адаптер был обучен Романом раньше. В этой итерации обучения нет. Проверяем его с нашим пулом кандидатов; это не полное воспроизведение исходного поиска Романа.

Qwen OCR · чтение надписей

B: выбранная область этикетки
  → Qwen3-VL-2B-Instruct
  → дословно видимые строки
  → поиск по тексту всего каталога
  → отдельный OCR Top20
       + визуальные списки B
  → объединение рангов

Читающая модель не получает список кандидатов или правильный ответ. Текстовая ветвь может добавить в выдачу вино, пропущенное визуальным поиском. Это отдельный опыт от Qwen Reranker.

Воспроизведение и дальнейшие шаги

Согласованный план и критерии · Живой план · Онбординг агентов

Корзины v2 неизменны. Новые прогоны добавлены в историю. Итеративный подбор на этих же фото — исследование, не независимый закрытый тест. TEST и PROD во время экспериментов не заменяем.

Исходные данные, закрытые ответы и веса хранятся отдельно от публичного отчёта.
