Как устроены решения

Статус проверен 26 сентября 2026, 03:17 МСК после выпуска ORT6 в TEST. Это снимок состояния, а не мониторинг в реальном времени. Экспериментальные метрики ниже относятся к ночному прогону; текущий сервис проверен отдельно.

  • CPU — активно в TEST: ORT6: SO400M FP32 в ONNX Runtime, 6 потоков, OWLv2 fallback 640.
  • GPU — активного сервиса нет. Экспериментальные RunPod удалены; B — контрольная архитектура.
  • CPU — предыдущий release: PyTorch SO400M whole-only, 4 потока; сохранён для отката.
  • GPU — основной кандидат: B → Roman-20 Deadline6. Roman-5 — более быстрая альтернатива.

  → RT-DETR: бутылки
  → SigLIP Base: центральное вино

  ├─ SO400M: целая цель → кандидаты

Для retrieval-корзин на входе уже проверенный кроп. Каталог обработан заранее. B — контроль для дополнительных этапов на GPU, а не новый результат этой ночи.

фото → RT-DETR R18: бутылки
  → SigLIP2 Base/224: выбор вина
  ├─ бутылка есть → кроп цели

До 26.09 работал на Sigma в lct-vision-test: CPU, PyTorch, 4 потока, один запрос одновременно. Версия rtdetr-so400m-whole-only-v1. Release сохранён для отката. Отдельной ветви эмбеддинга этикетки, OCR и объединения трёх ветвей здесь нет.

CPU · АКТИВНО В TEST С 26.09

ORT6 · оптимизированный whole-only

фото → RT-DETR → выбор вина
  ├─ бутылка есть → кроп цели
  └─ бутылки нет → OWLv2, размер 640
       ↓
  SO400M/384 FP32 → ONNX Runtime
       ↓                 6 потоков
  сравнение с каталогом → Top20

Работает на Sigma как lct-vision-test, версия rtdetr-so400m-whole-only-v1-onnx640. После выпуска health ready и публичный поиск Maks вернул пять кандидатов. В предшествующем эксперименте: 316/316 ответов в срок, p95 4,85 с на закреплённых корзинах и 4,96 с на фото организаторов. Эти числа относятся к эксперименту, а не к production SLA.

ЭКСПЕРИМЕНТ · НЕ ВЫБРАН

DISK + LightGlue · совпадение деталей

B: выбранная этикетка + Top20
  → DISK: характерные точки
  → LightGlue: пары точек
  → геометрическая проверка
  → новый порядок кандидатов

контроли:
геометрия / смесь / осторожный каскад

Например, совпали буквы, эмблема и рисунок в согласованном расположении. Много совпадений ещё не доказывает точный товар: у разных вин могут повторяться оформление и каталожная фотография.

GPU · АЛЬТЕРНАТИВНЫЙ КАНДИДАТ, НЕ ВНЕДРЁН

Qwen VL Reranker 2B · сравнение пары

B: выбранная этикетка + Top20
  → для каждого кандидата:
    фото запроса + фото эталона
    + название и поля каталога
  → Qwen: оценка соответствия
  → новый порядок кандидатов

Это проверка готового списка. Она не вернёт товар, которого нет в Top20, и не исправит неверно выбранную бутылку. Число модели не трактуется как откалиброванная вероятность точного совпадения.

GPU · ОСНОВНОЙ КАНДИДАТ, НЕ ВНЕДРЁН

B → Roman-20 Deadline6

полное фото + кандидаты B
  ├─ первые 5 → Qwen3.5-4B → выбор
  └─ группы из Top20
       → промежуточные выборы
       → финальные 5 → выбор
  → исходный порог + смесь с B

контроль: base / base + адаптер Ромы

Deadline6: B занял ≥6 с
  → вернуть свежий B без турнира

Основной кандидат — Roman-20 с Deadline6: 48/54 реальных размеченных фото, 315/316 ответов в срок. Roman-5 — более быстрая альтернатива: 46/54 и 314/316 в срок. Ни один не является активным GPU-сервисом.

Адаптер был обучен Романом раньше. В этой итерации обучения нет. Проверяем его с нашим пулом кандидатов; это не полное воспроизведение исходного поиска Романа.

ЭКСПЕРИМЕНТ · НЕ ВЫБРАН ДЛЯ ОНЛАЙН-ПУТИ

Qwen OCR · чтение надписей

B: выбранная область этикетки
  → Qwen3-VL-2B-Instruct
  → дословно видимые строки
  → поиск по тексту всего каталога
  → отдельный OCR Top20
       + визуальные списки B
  → объединение рангов

Читающая модель не получает список кандидатов или правильный ответ. Текстовая ветвь может добавить в выдачу вино, пропущенное визуальным поиском. Это отдельный опыт от Qwen Reranker.
