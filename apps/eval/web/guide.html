Как проверить
решение.

Читайте открытые данные без пароля. Токен нужен только для отправки прогона или частного разбора эталона.

1. Выберите трек

service получает полный кадр и возвращает одну карточку центрального вина: top-1 slug. Официальный контракт организаторов требует один slug. Действия no_match и insufficient_information — дополнительные продуктовые проверки этого стенда, не часть официального top-1 сценария.

retrieval получает проверенный кроп целевого вина. Верните упорядоченный список slug; стенд считает top-1, top-5, top-20 и MRR.

Каждый кейс принадлежит одному треку. Метка «из каталожного референса» означает, что запрос может быть связан с референсом и его результат нельзя считать независимой проверкой.

2. Получите открытые данные

Чтение корзин, изображений, галереи, отчётов и пакета доступно без пароля. Для POST /api/submissions нужен токен участника в заголовке Bearer; значение не записывайте в код или отчёты. Для частного разбора эталона нужен отдельный токен. Сервис получает их из /etc/lct-eval.env через переменные окружения LCT_EVAL_PARTICIPANT_TOKEN и LCT_EVAL_REVIEW_TOKEN. Для авторизованных агентов участнический токен находится в /srv/lct/eval-access/participant.env; токен разбора — в /srv/lct/eval-access/review.token. Эти файлы не раздаются через сайт и не входят в архив. Не помещайте токен в URL или файл submission.

BASE='https://cv.ops.dzap.pw'
curl "$BASE/api/baskets"
curl "$BASE/api/baskets/v2/download" -o lct-eval-v2.zip
# Только перед отправкой результата:
export LCT_EVAL_PARTICIPANT_TOKEN='<ваш токен>'

Архив содержит публичный манифест, изображения и при наличии список допустимых slug. В нём нет правильных ответов. Хеш каждого изображения и suite_hash связывают прогон с точной версией. На сервере бинарник находится в /srv/lct/maks/eval/current/lct-eval, набор — в /srv/lct/data/eval, а процесс запускается unit lct-eval.service. Права на файлы доступа назначает оператор; если доступа к ним нет, запросите токен у него.

PowerShell

$base = 'https://cv.ops.dzap.pw'
Invoke-RestMethod "$base/api/baskets"
Invoke-WebRequest "$base/api/baskets/v2/download" -OutFile lct-eval-v2.zip
# Только перед отправкой результата:
$env:LCT_EVAL_PARTICIPANT_TOKEN = Read-Host 'Participant token'

3. Запустите решение

Решение принимает POST /v1/eval/predict с multipart-полем image. Официальный контракт принимает HTTP 200/201 и JSON {"slug":"..."} либо первый элемент массива [{"slug":"..."}]. Для диагностического retrieval можно вернуть {"ranked_slugs":["...","..."]}. Лимит подключения 5 секунд, весь запрос — 10 секунд.

lct-eval run -suite-version v2 -source api -base "$BASE" -track service \
  -endpoint http://127.0.0.1:8080/v1/eval/predict \
  -submission-id my-service-001 -solution my-model -solution-version 0.1 \
  -commit abc123 -config-hash cfg1 -weights-version w1 -catalog-version c1

lct-eval run -suite-version v2 -source archive -archive lct-eval-v2.zip -base "$BASE" \
  -track retrieval -endpoint http://127.0.0.1:8080/v1/eval/predict \
  -submission-id my-retrieval-001 -solution my-model -solution-version 0.1

Для одной корзины добавьте -baskets IMG-09. Клиент проверяет SHA-256 входов, фиксирует ошибки и таймауты, отправляет фактические предсказания. Неполный submit допустим: пропущенные проверенные кейсы остаются в знаменателе.

4. Отправьте результат вручную при необходимости

Возьмите suite_hash, basket_id и case_id из GET /api/baskets. Запишите только фактический ответ вашего решения. Поле status:"ok" означает, что решение ответило, а не что ответ верен.

cat > submission.json <<'JSON'
{
  "submission_id":"my-service-002",
  "suite_version":"v2",
  "suite_hash":"<suite_hash из манифеста>",
  "track":"service",
  "basket_ids":["IMG-09"],
  "solution":{"name":"my-model","version":"0.1","commit":null,"config_hash":null,"weights_version":null,"catalog_version":null},
  "submitted_by":"agent",
  "results":[{"case_id":"case-000046","status":"ok","prediction":{"slug":"<фактический slug>"},"latency_ms":420}]
}
JSON
curl -H "Authorization: Bearer $LCT_EVAL_PARTICIPANT_TOKEN" \
  -H 'Content-Type: application/json' --data-binary @submission.json \
  "$BASE/api/submissions"

Для retrieval используйте "track":"retrieval", корзины и кейсы этого трека и "prediction":{"ranked_slugs":["first","second"]}. Не подставляйте неизвестный ответ ради заполнения поля: используйте фактическую ошибку/таймаут или оставьте кейс не запущенным.

5. Посмотрите результат

После submit откройте «Матрица прогонов». Столбец появится по submission_id. Повтор тех же данных вернёт прежний отчёт; другие данные с тем же ID дадут конфликт. Публичный отчёт показывает оценку каждого кейса, но скрывает ответы модели и эталон. API с токеном участника возвращает собственные предсказания; режим разбора с отдельным токеном показывает эталон.

curl "$BASE/api/runs"
curl "$BASE/api/runs/my-service-002"

Это доверенный стенд для регрессии и разбора: участник видит результат каждого своего кейса. Разделение файлов защищает эталон от случайной выдачи во входном пакете, но не делает набор слепым после повторных прогонов. Браузер не запрашивает и не хранит токен.

6. Пилот изображений и готовые бейзлайны

Галерея по винам · Отчёт эксперимента. Здесь отдельно хранятся каталожный референс, настоящая сцена, генерация и обычные аугментации. Условия запроса и фактические наблюдения разделены. AI-кадры явно отмечены; accepted означает прохождение визуального отбора пилота, а не полную проверку мелкого текста.

Файлы пилота: /srv/lct/data/vision/manifest.jsonl. Результаты распознавания: /srv/lct/data/vision-baselines/20260924. Для всех агентов инструкции: tools/vision-pilot/README.md и tools/vision-baselines/README.md в BrutForce. Замороженные корзины v1 не изменялись; синтетика пилота в них не добавляется.

7. Следующий эксперимент: составной поиск

Сравнение детекторов и аудит эталонов показывает следующий опыт без обучения: схемы, реальные фото, чёрно-белую ветвь, качество поиска и корректность отказов. Отчёт первого составного поиска заполняется только проверенными результатами. В нём реальные фото организаторов, абляции на замороженных корзинах, время этапов и расходы показаны раздельно. Пока отдельное измерение не закончено, таблица так и помечена.

Код и воспроизведение: аудит реальных фото и составной visual+OCR поиск. Локальные размеченные фото, уже бывшие в v1, не считаются независимой проверкой качества на новых данных.

8. Правила данных для любого агента

Начните с /srv/lct/AGENTS.md, затем /srv/lct/data/README.md. Постоянные правила: /srv/lct/guide/docs/agent-guide/DATA-RULES.md. В репозитории к ним ведут AGENTS.md и MAP.md.

Различайте исправность файла, фото для карточки, визуальный эталон ML и правильный ответ теста. Спорный эталон не возвращается в индекс через резервный архив. Исправления версионируются с причиной и SHA; старые прогоны не переписываются. Неоднозначные ответы видны в покрытии, но не подменяются догадками.

100 реальных фотографий организаторов проверены отдельным набором меток: 54 однозначных ответа, 3 неоднозначных, 43 без разрешённой связи с каталогом. Это локальная проверка, не официальный ключ. Закрытые метки никогда не передаются решению или на inference-сервер. В публичные отчёты попадают только разрешённые агрегаты.

Erratum frozen v1: 25 сентября исправлены ответы для 13 service и 7 retrieval случаев одного вина. API и матрица сохраняют исторические оценки v1. Для новых прогонов выбирайте v2 (те же 213 изображений, исправленный эталон). Переключатель версии не смешивает прогоны с разными suite_hash. Для старых предсказаний доступен отдельный исправленный пересчёт. Reviewer-инструмент tools/organizer-audit/correct_frozen_report.py применяет закрытый /srv/lct/data/vision-retrieval/20260925/annotation/frozen-v1-errata.json только после получения предсказаний. Он проверяет SHA исходных файлов и не меняет историю. Не обучайте и не настраивайте решение по ошибочному старому ответу.

9. Требования организаторов

Вводные и источники: ТЗ, ответы Telegram, HTTP-контракт и открытые вопросы. Конкурсный ответ, рекомендации приложения и диагностические метрики разделены. Архив исходников расположен вне публичного сайта.

Исходный контракт и протокол работы — README.md и AGENTS.md в репозитории сервиса.
