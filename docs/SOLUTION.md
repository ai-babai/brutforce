# Решение и подтверждённые результаты

Проверено по [контракту реального распознавания](../contracts/vision-serving.md), [F8 runtime manifest](../deploy/f8-runtime.json), частной квитанции TEST и PROD-выпуску [Actions `36377401071`](https://github.com/ai-babai/brutforce/actions/runs/36377401071) от 28.09.2026. Официальная цель — точное вино по фото и существующая карточка; 90–100% и <3 с — **цели**, не наблюдаемые характеристики этого выпуска.

## Какое решение действует

- В TEST и PROD: Go API и общий F8 CPU с закреплёнными `modelVersion`, `visionCatalogVersion` и `visionIndexVersion`. Приложение `d26afa3`, candidate `b0428147…`, display catalog `svoe-20260927-alpha-2035-v1` (manifest `d88c4454…`), рекомендации `display-text-attributes-winery-review-v2` из индекса SHA `f05f16c7…`. Полные SHA и effective-связку сверять с серверным release record. PROD доступен на [app.dzap.pw](https://app.dzap.pw); независимый HTTP smoke пройден, browser UI pending.
- F8 использует детектор/gate, визуальное SO400M-представление и версионированный поиск; текстовое подтверждение и OCR rescue помогают при визуальной неоднозначности. [Схема и границы](../ARCHITECTURE.md). Ответ конкурсного API — только допустимый organizer slug. Продуктовая карточка появляется только при проверенном отображении этого slug в display-каталог.
- GPU-кандидат исследован отдельно, но GPU-сервис не объявляется доступным runtime этого TEST; fallback-routing и его метрики требуют самостоятельного свидетельства. Синтетический reference-режим предназначен для разработки UI/API и не измеряет качество F8.
