# Решение и подтверждённые результаты

Задача — найти по фото этикетки точное вино и показать существующую карточку. Цели ТЗ — 90–100% и <3 с; эти цифры не являются измеренными показателями выпуска. Условия источников и способ проверки разделены [ниже](#источники-требований-и-проверки).

## Какое решение действует

- TEST и PROD используют Go API и общий CPU F8 с закреплёнными версиями модели, каталога и индекса. App `d26afa3`, candidate `b0428147…`, display catalog `svoe-20260927-alpha-2035-v1` (manifest `d88c4454…`). Рекомендации берутся из `display-text-attributes-winery-review-v2`, SHA `f05f16c7…`. Полная связка хранится в закрытой квитанции выпуска; [PIPELINE](../deploy/PIPELINE.md) описывает порядок сверки.
- Детектор/gate и признаки SO400M ищут кандидатов в версионированном индексе; текстовое подтверждение и OCR rescue помогают при неоднозначности. Конкурсный API выдаёт допустимый slug, приложение показывает карточку только при проверенном отображении slug в каталог. [Архитектура](../ARCHITECTURE.md).
- GPU и переключение на CPU при сбое остаются проектом отдельной проверки. Синтетический режим служит для разработки UI/API. Действующий [PROD](https://app.dzap.pw) работает на CPU F8; HTTP smoke пройден. Ops прошёл headless mobile text-путь главная → поиск → карточка → рекомендации на 390×844 и 320×640 без ошибок; визуальная геометрия, gallery/photo-result и физическая камера ожидают проверки.

| TEST, 28 сентября 2026, app `d26afa3` | 1 реальное фото с известным ответом, путь upload→search→card и рекомендации | CPU F8 на Sigma; модель CPU не зафиксирована | Ответ совпал; это проверка одного случая, без оценки общей точности |
| PROD, 28 сентября 2026, app `d26afa3` | 3 контрольных фото, оригинальный participant script; отдельно HTTP upload→search→card и DQ009/010 | CPU F8 на Sigma; модель CPU не зафиксирована | 3/3 непустых slug; 4,595 / 4,354 / 3,079 с; первый известный ответ совпал; gold остальных фото неизвестен |

Три запроса в TEST или PROD — **HTTP smoke**. Они не измеряют accuracy, F1, p95, нагрузку или качество камеры/UI. Для оценки нужны независимые фото с известными ответами, включая no-match, блики, частичные этикетки и несколько бутылок.

Исторические числа взяты из частного журнала проверок; PROD — из квитанции оригинального скрипта и HTTP smoke от 28 сентября 2026, связанной с [выпуском Actions `36377401071`](https://github.com/ai-babai/brutforce/actions/runs/36377401071). Доступ эксперта к первичным квитанциям и фото не подтверждён. Документы вошли в приватный `main` через PR #103 (`b451ecd`) и меняются отдельно от приложения `d26afa3`.

## Воспроизведение и ограничения

Исторический Repro проверил смешанный bundle из 50/50 файлов по SHA. Теперь [Python-код](../apps/vision/README.md) находится в Git, а набор из 32 внешних файлов данных прошёл отдельную SHA-проверку. [Комплект](ASSET-TRANSFER.ru.md) с весами, каталогом, индексами и media распакован повторно и прошёл Docker preflight. На пустой локальной БД dry-run DQ001–008 и DQ011, импорт 2 038 карточек, проверка БД и health/catalog smoke прошли. Точный индекс рекомендаций с SHA `f05f16c7…` воспроизведён переносным Python-генератором байт-в-байт. [Публичная папка](https://disk.yandex.ru/d/dHAXDPcitS-ZJQ) содержит 14 файлов с именами и SHA-256, совпадающими с локальными оригиналами (13 файлов перечислены в `SHA256SUMS`); архивы по ссылке не скачивались, права на их распространение не подтверждены. Visual-neighbors из vision bundle не заменяют рекомендации.

После переноса кода оба linux/amd64-образа собраны на OrbStack; полный Compose достиг состояния healthy, vision подтвердил SHA импортированных Python-модулей и lexicon. Это проверка локального запуска, **не** паритет распознавания: чистый Linux, контрольный ответ по фото и OCR parity не подтверждены; версия Tesseract в образе может отличаться от серверной 5.5. Эмуляция запроса за 25 с не проходит лимит 10 с оригинального скрипта и не доказывает цель <3 с. PROD работает отдельно через systemd.

## Источники требований и проверки

- **ТЗ организатора:** сохранённый выданный текст сверяли 28 сентября 2026. Требуются воспроизводимый запуск, README с env/ограничениями, ARCHITECTURE с обработкой, поиском, карточкой и дополнительной функцией, доступные модель/данные/индекс. Текст ТЗ закрыт; доступного эксперту URL первоисточника в репозитории нет, перед отправкой сверить с актуальной версией у организатора. Цели 90–100% и <3 с относятся к ТЗ.
- **Оригинальный проверочный скрипт:** отдельно от ТЗ проверяет multipart-поле `image`, HTTP 200/201 и непустой `slug` в объекте или первом элементе массива; наш API возвращает объект. Лимиты клиента: 5 с соединение, 10 с на запрос. [Контракт API](../contracts/eval-predict.md) описывает серверную сторону. Скрипт не рассчитывает accuracy без gold; первичный файл не раскрыт в Git.
- **Форма сдачи:** четыре поля — репозиторий, документация, презентация, прототип. [Адреса и статусы](../README.md) приведены на входе; ссылка на презентацию пока не подтверждена. Исходная форма не опубликована в Git.

## Презентация и права

Проверенного адреса презентации пока нет; ссылку добавят после утверждения файла и прав. Фото пользователей и скриншоты с персональными данными не публикуются. Лицензия команды на код не согласована. Права на дизайн-референсы, каталог, датасет и веса проверяются раздельно; отсутствие лицензии не разрешает их повторное использование.
