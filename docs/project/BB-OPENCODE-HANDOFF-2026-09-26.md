## Задачи и агенты

Каноническая очередь: [GitHub Project #2](https://github.com/users/ai-babai/projects/2), repo `ai-babai/brutforce`. Для каждой задачи: область, инициатор, исполнитель, критерий готовности, ссылка на сессию/ветку/commit и результат проверки. Сначала поиск дубликата. Код FE/BE/ML/INFRA + номер GitHub issue. Исторический `docs/agent-guide/BOARD.md` описывает базовые правила; текущая автоматизация Sigma подробнее в `/srv/agents/sigma/TEAM.md`.

Серверная Sigma: Hermes в `/srv/agents/sigma`, Telegram [@sigma_lct_bot](https://t.me/sigma_lct_bot). Бот принимает доверенные учётные записи Макса и Ромы; `sigma-team.service` раз в минуту смотрит открытые Backlog с исполнителем «Команда Sigma». OpenCode — основной исполнитель, Codex CLI — альтернатива. Один автозапуск одновременно. Ход: Backlog → В работе → Sigma verification → Human verification → Done; Done решает человек. Повтор старой задачи требует явного разрешения, изменение карточки само по себе не перезапускает попытку. Команды и отмена — `/srv/agents/sigma/TEAM.md`. По умолчанию новая Telegram-задача Макса назначается «Айка», Ромы — «Агент-Ромы»; чтобы сработал диспетчер Sigma, нужно **явно** назначить «Команда Sigma» + Backlog. Из bb локальный OpenCode не становится этим серверным исполнителем автоматически.

Работая **от имени Sigma**, GitHub API/PR/push — только через `aika-ai-agent`; перед записью проверить личность по `/srv/agents/sigma/GITHUB.md`. Локальный агент Макса в bb использует свою настроенную учётную запись. Не переносить ключи, токены и полный транскрипт Codex между приложениями.
