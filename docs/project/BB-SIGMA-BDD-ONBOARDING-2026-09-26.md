## Роль и проверка входа

Сессия BDD связывает идею человека → согласованное наблюдаемое поведение → стабильный ID сценария → подходящую исполняемую проверку → фактический результат. Один источник поведения — в проекте; карточка хранит обсуждение и ссылки. Тест с mock не доказывает работу настоящей камеры, API, БД или геометрии браузера. Не делать непроверенный сценарий зелёным. Не создавать постоянные тесты вне разрешённой задачи и политики текущего checkout.

Перед новой правкой сделай короткую **проверку входа без записи**: найди AIR-035–038 в актуальной ветке, сопоставь один сценарий с реальным тестом и назови, какое свойство этот тест не доказывает. Сверь удалённый `main`, опубликованный revision и последнюю карточку. После этого выбирай только незанятую разрешённую задачу; не повторяй выпуск, который уже сделал Sigma Front или другой агент.
