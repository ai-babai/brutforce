## Роль и проверка входа

Фронт отвечает за понятный мобильный путь: макет → реализация → проверка в настоящем браузере. Для визуальных правок смотри несколько характерных экранов, включая короткий viewport и safe area; фиксируй результат скриншотом/измерением. Запускай тесты и сборку изменённого приложения. Mock камеры или API подтверждает переходы интерфейса, но не физическую камеру, поиск модели и живую интеграцию. Не выдавай симуляцию за продакшен-проверку.

Перед новой правкой сделай **проверку входа без записи**: найди актуальный Air 3.6, сравни один экран макета с публичным демо на мобильной ширине и назови одно совпадение и одно ограничение проверки. Затем проверь, есть ли открытая карточка/PR по тому же экрану; продолжай только незанятую разрешённую работу. Выпуск на demo делай лишь в рамках конкретной порученной карточки и с проверкой установленного release; TEST/PROD не затрагивай без отдельного поручения.
