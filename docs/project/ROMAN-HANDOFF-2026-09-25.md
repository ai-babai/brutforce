## Что именно делают модели

Это обученные **сравнители кандидатов**, не новые детекторы или поисковые энкодеры.

```text
Фото → исходный поиск Романа → 5 карточек-кандидатов
                                + фото каждой карточки
                                + каталожные атрибуты
                                ↓
                 Qwen3.5-4B + QLoRA (языковые слои)
                                ↓
                     кандидат 1…5 либо none
                                ↓
             ограниченное объединение с исходными scores
                                ↓
                      итоговый порядок карточек
```

Важно: исходные590 уже получены сложной композицией с ранее обученными компонентами.
Это не результат одного SigLIP и не baseline без обучения:

```text
SigLIP-поиск + разные виды бутылки
  → OCR: Qwen-VL, Qwen3.5, Paddle v5/v6 + текст каталога/эталонов
  → согласование OCR и конфликтов сахара
  → прежний Qwen-адаптер + Qwen3-Reranker-8B
  → сравнение групп кандидатов Qwen + полный кадр + geometry route
  → сохранённые scores 590/715
  → новый fullframe adapter → 591 → RR20 → 592
```

Цепочка подтверждается `docs/research/CYCLE-003.md`,
`src/vino_research/cycle3_sugar_ablation.py`, `cycle3_ocr_consensus.py`,
`cycle3_fullframe_trained_validation_data.py` (parent geometry-view-route-full715-v1).
Некоторые промежуточные parent-run артефакты исключены из компактной передачи.
Пересчитать сохранённые итоговые метрики можно; полностью восстановить весь590-пайплайн
из этого пакета пока не подтверждено. Это ещё один довод сначала взять адаптер отдельно,
а не переносить весь исследовательский каскад в наш online-сервис.

RR20 отдельно расширяет пул до20: сравнивает группы, затем финальные5.
Нельзя приписывать изменение пула исключительно весам адаптера.
Base revision: `Qwen/Qwen3.5-4B@851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`.
В adapter config есть Windows-путь: при воспроизведении явно разрешать pinned base;
не копировать .venv и не скачивать floating main.
