# Реестр зон проекта

Проверено по checkout приложения 2026-09-20. Это описание существующих зон, не требование их переносить.
По аналогии с infra-os: короткая карта → конкретная зона → её контракт, команды и результат проверки.
Одна таблица пока достаточна; YAML-реестр, ADR-каталог и отдельную управляющую платформу не создаём.

| Зона | Назначение и состояние | Вход |

| contracts/ | Канонические машинные интерфейсы и схемы | contracts/README.md |

## Существующие серверные зоны

- /srv/lct/repo — общая интеграционная копия; может отставать, проверяй SHA.
- /srv/lct/work/<task> — рабочие копии задач, отдельные ветки.
- /srv/lct/maks — зона Макса; behavior-demo/releases и current, макеты и отчёты.
- /srv/lct/roman — зона Романа и его отчёты.
- /srv/lct/prod — выделено для боевого приложения; наличие папки не доказывает готовность production.
- /srv/lct/data/{maks,roman,prod} — постоянные данные вне Git; фото не входят в релиз приложения.
- /srv/lct/notes, guide — операционные записи и вход участников; не дублировать здесь канонические правила вручную.
- /srv/infra — серверные инструкции восстановления; infra-os хранит регистрацию инфраструктуры.

## Веточная реальность

Приложение развивается в codex/behavior-demo (PR20); выбранные макеты v2 — в codex/camera-viewport.
main на момент фиксации ещё не содержит приложение. Не выдавай наличие файла в другой ветке за наличие в текущей.
Переход к коротким рабочим веткам от интегрированного main — следующий согласуемый шаг, не автоматический merge.

## Ещё не реализовано

PostgreSQL продукта, SQL-миграции, disposable DB, единая команда выпуска и ML leaderboard пока предложения.
Не создавай пустые apps/ml, inventory, db и другие каталоги, пока нет реального содержимого.
Модель и индекс Ромы описываются по фактическому месту реализации после согласования контракта.
