# Runbook приёма данных Vino

Использовать для `VINO-001`. До получения фактических ресурсов команды являются
шаблоном процедуры, а не заявлением о выполнении.

## До загрузки

1. Зафиксировать владельца/источник, назначение, условия доступа и права.
2. Уточнить, какие файлы являются catalog, public test, private test и
   дополнительными материалами.
3. Не помещать токены, cookies и подписанные URL в Markdown или shell history.
4. Выбрать локальный каталог `Dataset/00_raw/<NN_source>/` и добавить источник
   в `Dataset/REGISTRY.yaml`.

## Приём

1. Сохранить исходные байты без преобразования.
2. Рассчитать SHA-256 и размер каждого файла.
3. Для архива проверить список путей, абсолютные пути и `..` до распаковки.
4. Не запускать исполняемые файлы и скрипты из набора.
5. Создать `Dataset/91_manifests/<source-id>-v1.jsonl` и краткий
   `runs/<date>-data-intake/REPORT.md`.

## Профилирование

- формат/схема/кодировка каталога;
- количество строк, уникальных `slug`, missing/duplicate IDs;
- число изображений, декодируемость, MIME, размеры и ориентация;
- точность связи изображения с продуктом;
- дубликаты байтов и perceptual near-duplicates;
- распределение условий съёмки: перспектива, блики, размытие, фон, occlusion;
- заявленные права и ограничения публикации.

## Выходной gate

- Raw неизменён и исключён из Git.
- Хеши воспроизводятся.
- Все объекты отражены в manifest либо quarantine list.
- Неоднозначные `slug`/identity не исправлены молча.
- Public/private границы описаны.
- Указаны раздельные статусы `training_use`, `redistribution` и
  `derivatives`; некоммерческая цель не считается универсальной лицензией.
- В `WORKING.md` оставлен один следующий шаг: аудит идентичности либо запрос
  недостающих сведений.
