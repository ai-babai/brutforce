# Протокол оценки Vino

Статус: draft для заморозки после аудита данных. Протокол нельзя подгонять под
результат уже выполненного эксперимента.

## Единица оценки

Один query image → один expected `slug` либо explicit unknown. Результат
top-1 считается правильным только при точном совпадении нормализованного
каталожного `slug`; ручная семантическая «почти правильность» не засчитывается.

## Обязательные метрики

- `top1_accuracy` — доля exact slug совпадений.
- `top5_recall` — доля query, где expected slug находится в первых пяти.
- `macro_f1` — macro F1 по классам с явно указанной политикой классов без
  support; не смешивать с top-1 accuracy.
- `mrr` — диагностическая позиция правильного кандидата.
- `coverage` и `selective_accuracy` — качество при включённом abstention.
- `unknown_precision/recall/F1` — качество `not_found`, если есть unknown set.
- `top1_top2_margin` и калибровка — диагностические распределения, не
  «вероятность» без calibration test.
- latency `p50/p95/p99`, cold/warm отдельно, плюс время по этапам pipeline.

## Обязательные срезы

- near-duplicate и обычные позиции;
- производитель/серия/категория/год при наличии;
- перспектива, блики, размытие, низкое освещение, частичная этикетка;
- seen/unseen capture conditions;
- unknown/out-of-catalog;
- public test и untouched holdout отдельными строками.

Для каждого среза указывать `n`; маленький sample не скрывать за процентом.

## Защита от утечки

- Split фиксируется до model selection.
- Original, crop, augmentation, transcoded copy и прочие derivatives остаются в
  одной split-группе.
- Product identity и заранее определённая near-duplicate family не пересекают
  train/validation/test, если цель теста не требует поиска по эталону; в таком
  случае catalog reference отделён от query и описан явно.
- Public test не используется для fine-tuning и выбора порога после просмотра
  результатов; итеративный public leaderboard помечается как validation-like.
- Private test не исследуется и не кэшируется в pipeline.

## Артефакт эксперимента

Каждый значимый `runs/<date>-<name>/` содержит:

- `REPORT.md` с гипотезой, результатом, ошибками и ограничениями;
- machine-readable config;
- версии и SHA-256 dataset/split/index/model;
- code revision или hash исходников;
- seed и детерминизм;
- оборудование, runtime и зависимости;
- raw aggregate metrics и confusion/error manifest без закрытых изображений.

## Gate изменения

Новый кандидат принимается только если:

1. Он превосходит зафиксированный baseline на заранее названной основной
   метрике или улучшает важный срез без неприемлемой регрессии.
2. Результат воспроизводится повторным запуском.
3. Независимый `qa_evaluator` проверил split, вычисление метрик и отсутствие
   очевидной утечки.
4. SLA и ресурсная цена указаны, даже если скорость не является блокером.

Целевые 90–100% из ТЗ являются ориентиром приёмки, а не основанием скрывать
неудачные классы или исключать трудные примеры.
