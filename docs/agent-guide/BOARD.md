# Доска BrutForce

Каноническая очередь: https://github.com/users/ai-babai/projects/2 (приватная).
Репозиторий: https://github.com/ai-babai/brutforce. Project owner ai-babai, number 2.

## Как работать

- Область Area: Frontend, Backend, ML или Infra. Выбирай одну основную.
- Статус: Backlog → В работе → Проверка → Done. Отдельной доски тестирования нет.
- Обязательные сведения: инициатор идеи, цель, область и критерий готовности. Перед началом — исполнитель и поле «Агент / сессия» с идентификатором/ссылкой. Автор GitHub отражает техническую учётную запись; инициатора не подменять именем агента.
- Голосовое поручение оформляет агент: сначала ищет дубликат, затем создаёт issue, добавляет в Project, заполняет поля и возвращает ссылку. Неизвестного инициатора уточнить, не выдумывать.
- Перед началом перечитай карточку и проверь, что её не взял другой агент; отметь сессию, ветку и область изменений. Это координация, не атомарная блокировка.
- После выполнения приложи PR/commit или артефакт и фактическую проверку; переведи в «Проверка». Done — после выполнения критериев и проверки, а не просто окончания сессии; issue закрыть completed. Отменённое закрыть not planned и пояснить причину.
- Блокер: label blocked и причина/следующий шаг. Гипотеза: label hypothesis, ожидаемый эффект и способ проверки, на той же доске.
- Карточка в Backlog не разрешает запуск работ вне текущего поручения. Продуктовые решения не выдумывать. Правила проекта о проверках сохраняются.
- /srv/lct/notes/activity — короткие технические записи сессии со ссылкой на карточку, не второй список задач. inbox — знания и находки.

## Доступ и команды агента

Используй свою разрешённую GitHub-аутентификацию с доступом к приватному репозиторию и Project. SSH deploy key сервера позволяет Git clone/push, но НЕ даёт доступ к API доски. Не копируй личный широкий токен Макса на общий сервер. Пока отдельная авторизация серверного агента не настроена, обновления доски делает локальный агент с доступом; серверный оставляет ссылку и результат в activity и сообщает, что статус не обновлён.

Просмотр: `gh project item-list 2 --owner ai-babai --format json`.
Поля и актуальные option IDs: `gh project field-list 2 --owner ai-babai --format json`.
Создание: `gh issue create --repo ai-babai/brutforce --title '...' --body-file task.md`.
Добавление: `gh project item-add 2 --owner ai-babai --url ISSUE_URL`.
Изменение полей: `gh project item-edit` с ID карточки/поля, полученными через CLI; не путай issue number с project item ID.
Для карточки достаточно разделов: Инициатор; Цель; Критерий готовности; Исполнитель/сессия; Результат и проверка.

## Коды задач

Заголовок: `INFRA-002 · Заменить заглушку приложением Романа`.
Префиксы: Frontend → FE, Backend → BE, ML → ML, Infra → INFRA.
Число — настоящий номер GitHub issue, минимум три цифры (001, 027, 1234). Отдельного счётчика по областям нет. Код уникален внутри BrutForce; между проектами добавляй название репозитория или ссылку.
При создании сначала получи номер issue, затем допиши код в заголовок. Для смены основной области обнови Area и префикс одновременно; номер и URL сохраняются. Не создавай новую карточку ради смены области. В ссылках между задачами используй GitHub #номер/URL, чтобы переименование не ломало связь.
Одна задача — один проверяемый результат. Готовность DNS/заглушки и готовность приложения — разные результаты; завершённое отмечай с доказательством, оставшуюся работу называй явно.

## Исполнитель Sigma

Поле «Исполнитель»: Макс, Роман или Sigma; инициатор и агент/сессия остаются отдельными полями. Назначение Sigma означает поручение выполнить описанную задачу в пределах его прав. Агент выбирает только свои открытые Backlog без blocked, по одной, с проверкой каждые 15 минут. Остальные Backlog сами не запускаются. Опасные изменения требуют отдельного поручения даже у назначенной карточки. До завершения INFRA-005 GitHub-доступ Sigma не подключён: таймер ждёт отдельную авторизацию, задачи не забирает.
