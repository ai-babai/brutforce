# PostgreSQL: общая работа и эксперименты

## Устройство

Один нативный PostgreSQL 18 на sigma-ops, без Docker. Доступ только через
127.0.0.1:5432 или Unix socket; с компьютера подключайтесь через SSH-туннель.
Не открывайте порт БД в интернет. PostgreSQL Buzz — отдельный сервис.

| База | Назначение | Настройки на Sigma |
|---|---|---|
| lct_shared | Общая интеграционная сборка Макса и Ромы | /etc/lct-db/shared.env |
| lct_maks | Эксперименты фронта/бэка Макса | /etc/lct-db/maks.env |
| lct_roman | Эксперименты модели/данных Ромы | /etc/lct-db/roman.env |
| lct_test_shared / lct_test_maks / lct_test_roman | Тестовые базы по зонам | Через тестовый инструмент |

Это отдельные базы, не синхронные копии. У приложения один DATABASE_URL.
Общие изменения проверяются в своей зоне, проходят Git review/merge, затем
применяются к lct_shared. Не запускайте экспериментальные DDL в общей базе.
Перенос каталога между средами — явный импорт версии данных, не копирование datadir.
Боевой lct_prod пока не создаём. Общая база сейчас — интеграционная, не production.

## Доступы

У каждой постоянной базы отдельно runtime и migration роли. Runtime использует
CRUD, migration меняет схему; приложение не получает superuser или CREATEDB.
Файлы настроек доступны root и группе lct. Макс и Рома работают под общим lct,
поэтому это защита от случайных ошибок приложения, не изоляция людей друг от друга.
Не печатайте env, пароли и полные URL в чат, логи, Git или карточки.
Hermes передаёт разработку исполнителю; доступ к БД не меняет эту обязанность.

## Схема и данные

Сейчас подготовлена инфраструктура; продуктовые таблицы и подключение Go API
выполняются отдельным изменением приложения. Наличие БД не означает, что демо её использует.
SQL-миграции хранить в apps/api/migrations, когда появится первая реальная миграция.
Для Go выбран SQL-подход с Goose; не заводить второй независимый мигратор в Python.
Уже применённые файлы не переписывать. Изменение схемы, код и инструкция идут в одном PR.

Каталог импортировать версиями с checksum и исходным точным slug. Изображения,
веса модели и индексы остаются в /srv/lct/data; в БД — ссылки и метаданные.
Не загружать исходный датасет в Git и не удалять оригиналы при импорте.

## Проверки и выпуск

Тестовые базы заранее созданы: агентам не нужен sudo для их подготовки.
В каждой зоне одновременно работает один DB-прогон; зоны проверяются параллельно.

1. Быстрые проверки логики работают без БД.
2. Для интеграции подготовить тестовую БД, применить миграции и малый seed.
3. Проверить установку с нуля и обновление предыдущей схемы с сохранением данных.
4. После принятия изменений применить их к общей сборке, проверить приложение.
5. Очистка затрагивает только свою зарегистрированную тестовую среду.

Нельзя сбрасывать lct_shared, lct_maks или lct_roman ради запуска тестов.
Используйте совместимые миграции: сначала добавить, перенести данные, переключить код;
удаление старого — отдельным изменением. Откат приложения не означает откат данных.
Не обещайте быстрый полный импорт датасета на основании времени пустой тестовой БД.

## Операционные команды

Точные установленные команды, резервное копирование и восстановление:
[DATABASE-OPS.md](DATABASE-OPS.md), серверная копия /srv/infra/lct-db/DATABASE.md;
регистрация инфраструктуры находится в infra-os, deployment sigma-lct-postgres.
При изменении команд обновляйте этот документ и серверную копию в одной задаче.

OpenCode работает в сетевой среде opencode-nl. Используйте предоставленный
DATABASE_URL с Unix socket: localhost агента не совпадает с localhost сервера.
Для SQL-клиента с компьютера используйте SSH-туннель и localhost TCP-настройки;
пароль берётся из защищённого env, а не из документации.
