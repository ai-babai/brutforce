# PostgreSQL: общая работа и среды

## Устройство

Один нативный PostgreSQL 18 на sigma-ops, без Docker. Доступ только через Unix socket или localhost.
Не открывайте порт БД в интернет; подключение с компьютера — через SSH-туннель.

| База или среда | Назначение | Статус |
|---|---|---|
| `lct_shared` | Общая интеграционная БД | подготовлена |
| `lct_maks`, `lct_roman` | Изолированные эксперименты Макса и Романа | подготовлены |
| `lct_test_shared`, `lct_test_maks`, `lct_test_roman` | Disposable БД для проверок по зонам | подготовлены |
| `/srv/lct/stage`, `test.ops.dzap.pw`, `lct_shared` | Общая тестовая среда | подготовлена |
| `/srv/lct/prod`, `app.dzap.pw`, `lct_prod` | Production-цель | подготовлена, не задеплоена |

Это отдельные БД, не синхронные копии. Папка, домен или БД не доказывают работающий сервис.
Общие изменения проверяются в своей зоне, проходят PR в `main`, затем применяются к `lct_shared`.
Подробный порядок выпуска и отката: [PIPELINE.md](../../deploy/PIPELINE.md).

## Доступы, схема и данные

У каждой постоянной БД отдельные runtime и migration роли. Приложение не получает superuser или CREATEDB.
Не печатайте env, пароли и полные URL в чат, логи, Git или карточки.

SQL-миграции Go API хранятся в `apps/api/migrations`; используется Goose, без второго мигратора в Python.
Уже применённые миграции не переписывают. Изменение схемы, код и инструкция идут в одном PR.
Изображения, веса модели и индексы остаются в `/srv/lct/data`; в БД — ссылки и метаданные.

## Проверки и выпуск

1. Быстрые проверки логики работают без БД.
2. Интеграция использует зарегистрированную тестовую БД, миграции и малый seed.
3. Проверь установку с нуля и обновление предыдущей схемы с сохранением данных.
4. После PR в `main` применяй изменения к общей тестовой среде только по runbook.
5. Очистка затрагивает только зарегистрированную тестовую среду.

Не сбрасывайте `lct_shared`, `lct_maks`, `lct_roman` или `lct_prod` ради тестов.
Откат приложения не означает откат данных. Не выдавайте время пустой БД за время полного импорта каталога.

Перед PROD контроллер выпуска создаёт backup `lct_prod`; это не ручной шаг каждого тестового прогона.
Точные команды, политика retention и восстановление: [DATABASE-OPS.md](DATABASE-OPS.md) и
[PIPELINE.md](../../deploy/PIPELINE.md).
