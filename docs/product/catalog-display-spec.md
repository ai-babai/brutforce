## От свободной идеи к проверяемому поведению

Пользователь открывает каталог на телефоне, ищет вино, рассматривает бутылку и
проверяет происхождение сведений. Ему не нужны 2038 загрузки сразу или выдуманные поля.
Первая страница — 24 записи, максимум API — 60; «Показать ещё» продолжает ту же выборку.
Изображения — файлы, мета и ссылки — БД. Модель распознавания остаётся заглушкой.
Каталог и ручной поиск используют `/v2/catalog`; детали — `/v2/catalog/{slug}`.
Миграция major-версии описана в [правилах версий](../../contracts/api-versioning.md#be-045--каталог-v2).

## Конкретные проверочные примеры

1. **CAT-001.** Быстрый набор содержит 73 синтетических canonical ID и aliases.
   Без limit возвращаются 24 записи; полный обход возвращает все 73 ровно один
   раз в порядке ID (первоначально ID совпадает со slug). Запрос limit=60 ограничен 60; 0, 61 и нечисловое значение
   дают 400. Cursor другого q даёт 400, другой версии — 409.
2. **CAT-002.** Запись за первой страницей находится и через «По названию»
   с главной, и после «Открыть каталог». Оба пути вызывают GET с q.
   При смене q во время загрузки следующей страницы прежний запрос отменяется;
   его поздний ответ игнорируется. Повтор ошибки сохраняет q, пустая выдача
   не показывается как сетевой сбой. Лупа и Enter имеют одинаковое действие.
3. **CAT-004/005.** Отдельные минимальные синтетические записи содержат
   отсутствующие год/объём, невалидную крепость, валидный диапазон крепости
   и каждую из трёх спорных проекций. Ожидаемые разрешённые поля задаются
   из требования; сравнение не вычисляет их тем же mapper, который проверяется.
4. **CAT-006.** Проверяются все три aliases и отсутствие их ID в списке/поиске.
   HTTP-тест с подменённым store проверяет форму ответа; PostgreSQL-тест
   отдельно подтверждает реальное разрешение сохранённых aliases.
5. **CAT-007.** Компонент получает допустимый reference-ответ с настоящей
   карточкой: source URL/дата видны, заглушка распознавания обозначена,
   утверждения «карточки синтетические» нет. Это проверка UI-границы.
   Реальный несовместимый reference-сервис возвращает явную ошибку;
   этот пример не требует успешного распознавания отсутствующей моделью.
6. **CAT-008/009.** Полный snapshot A сравнивается после dry-run B,
   ошибки валидации B и ошибки после начала записи B. Успех B и повтор B
   дают одинаковое содержимое; seed/migration сохраняют B, SQL NULL и aliases.
   Restore A проверяется повторным чтением, а не только отсутствием ошибки.
   Невалидные path/hash/dimensions/type/bytes/aliases отклоняются до мутации.
   Symlink направлен на существующий валидный файл: ошибка не может быть
   следствием отсутствующего target. Каждый negative fixture валиден
   по остальным условиям до внесения проверяемого повреждения.
7. **REPORT-004.** Когда Go-проверка сценария падает, а UI-проверка того же ID
   проходит, итог сценария failed и сохраняет оба свидетельства. Два ID
   в имени теста учитываются оба. Незапущенные уровни проверки не становятся
   пройденными из-за успешного другого уровня.
8. **CAT-003/SR-009.** В браузере проверяются 320/390/desktop, DPR 1/2/3,
   увеличенный текст, currentSrc и сетевые запросы изображений, contain,
   отсутствие горизонтального переполнения, фокус и отложенная загрузка.
   Быстрые DOM-assertions проверяют атрибуты, выбор карточки и fallback.
9. **CAT-010/011.** Запись `search-rank-40-exact` содержит название
   «Ёжевичный Резерв», винодельню «Шато-Тамань» и год 2021. Запрос
   `  2021, ШАТО!!! резерв ежевичный  ` находит её независимо от порядка и полей.
   `резевр шато 2021` также находит её по одной соседней перестановке.
   `вичн`, `202`, `2022`, `!!!`, слово с двумя правками и запрос с добавленным
   `мусор` её не находят. Внутренняя подстрока не заменяет префикс слова.
10. **CAT-012/013.** Для запроса `ежевичный резерв шато 2021` записи
    `search-rank-40-exact`, `search-rank-50-exact`, `search-rank-20-partial`
    («Ёжевичный Резервный», «Шатонский») и `search-rank-10-typo`
    («Ёживичный Резерв») идут именно в этом порядке. При `limit=2` две страницы
    дают те же четыре ID без повторов. Пустой `q` обходит fixture в порядке ID.
    Cursor с другим `q` даёт 400, с другой версией — 409. Старый формат search
    cursor после смены matcher даёт 400; прежний cursor пустого каталога валиден.
11. **CAT-014.** Тот же fixture загружается в отдельную PostgreSQL. HTTP-обход
    повторяет порядок и границы страниц CAT-012/013; проверка фиксирует, что
    store материализует полные карточки только после выбора ID текущей страницы.
    Неподходящая поиску poison-запись с невалидным тяжёлым metadata не должна
    ломать выдачу: для ранжирования она читается только в лёгкой проекции.

## Динамический поиск по мере ввода · FE-052

Инициатор: Макс. Основание: [поручение #52](https://github.com/ai-babai/brutforce/issues/52),
прочитано 22.09.2026. Формулировка и проверка BDD: Astra.
Этот раздел уточняет момент отправки и состояния ручного поиска CAT-002;
правила backend CAT-010…014 и фото-путь остаются прежними.

После первого непустого символа запрос отправляется через 250 мс после
последнего изменения ввода. Проверяется непустота после внешнего trim;
префиксы, регистр, ё, опечатки и порядок определяет существующий backend.
Поле и результаты находятся на одной странице. Каталог не загружается целиком.

| ID | Дано | Когда | Тогда |
|---|---|---|---|
| CAT-015 | Открыт ручной поиск | Введён хотя бы один непустой символ; прошло 250 мс без нового ввода | Отправлена первая страница с limit=24 и текущим q без cursor; загрузка, результаты, пустая выдача и ошибка с повтором показаны под доступным полем; фокус и позиция курсора не теряются; один результат не открывает карточку автоматически |
| CAT-016 | Запрос A или его следующая страница ещё выполняется | Ввод изменён на B | Уже в событии ввода отменяются прежний запрос и таймер; ответы A, включая ошибки, сразу считаются устаревшими, даже до отправки B; после 250 мс запрашивается только последнее значение |
| CAT-017 | Есть текст, отложенный запрос либо запрос в полёте | Поле очищено или пользователь покинул поиск | Очистка немедленно отменяет старую работу и запрашивает первую страницу без q/cursor; уход отменяет таймер и запрос без новой загрузки; поздние ответы не меняют текущий раздел |
| CAT-018 | Набирается текст либо ожидается таймер | Завершается IME-композиция или нажаты Enter/«Искать» | Во время композиции запрос не отправляется; после compositionend действует обычная задержка 250 мс; Enter/кнопка вне композиции отправляют актуальное значение сразу и убирают отложенный дубль |
| CAT-019 | Получена первая страница для q=A | Нажаты «Показать ещё» или введён q=B | Продолжение использует только cursor текущей A и её q, добавляет страницу в backend-порядке; изменение на B сразу делает старый cursor недоступным и начинает новую выборку; поздняя страница A не добавляется к B |
| CAT-020 | Ручной поиск открыт через «По названию» либо нижний «Поиск» | Пользователь вводит текст, явно выбирает карточку и возвращается назад | Оба входа имеют одинаковое inline-поведение; открывается выбранный ID; возврат сохраняет текст, выданные страницы, cursor, порядок и прокрутку списка без повторного поиска; клавиатура не открывается принудительно |

### Точные границы событий и проверок

- **Задержка, CAT-015/016:** ввод `к`, затем `ка` через 100 мс. До 249 мс
  после последнего ввода запросов нет; на 250 мс — один запрос `ка`.
  Ответ не заменяет страницу отдельным loading/missing/error-экраном.
  Во время задержки статус «Обновляем результаты…», во время запроса —
  «Ищем вина…». Поле не заменяется другим DOM-элементом и не блокируется;
  обновление выдачи не вызывает повторную установку фокуса во время печати.
  Варианты ответа: ноль, один и несколько кандидатов; ошибка даёт inline-повтор
  того же актуального q. Ответ одного кандидата ждёт явного выбора человеком.
- **Немедленная инвалидация, CAT-016:** запрос A уже отправлен; ввод B меняет
  актуальную выборку немедленно. Успех и ошибка A, доставленные через 100 мс
  после этого ввода, не меняют кандидатов, ошибку или загрузку B. Проверить
  отдельно даже транспорт, который завершает promise после abort.
- **Очистка и уход, CAT-017:** проверить оба момента — до срабатывания таймера
  и после отправки запроса. Пробельное значение эквивалентно пустому.
  Очистка выполняет один GET первой страницы каталога; оставшийся таймер
  не посылает второй запрос. Уход в Главную/Сохранённое не запускает каталог
  и не позволяет позднему success/error вернуть поиск. Открытие карточки
  также отменяет незавершённую поисковую работу.
  Явная кнопка очистки имеет доступное имя и область нажатия не меньше 44 px,
  сохраняет фокус поля; это не правило автоматического фокуса при навигации.
- **Клавиатура, CAT-018:** compositionstart отменяет ожидающую/текущую работу;
  промежуточные composition/input и Enter для подтверждения композиции
  не отправляют HTTP. После compositionend отправляется только итоговый текст.
  Вне композиции Enter и кнопка немедленно исполняют ожидающий запрос;
  продвижение часов за старые 250 мс не добавляет дубль. Если тот же запрос
  уже в полёте, повторный submit не создаёт второй параллельный запрос.
  Явный повтор завершившейся ошибки допускается сразу. Submit пустого поля
  не повторяет загрузку, уже вызванную очисткой.
- **Страницы, CAT-019:** получить cursor A, начать продолжение, ввести B,
  доставить старую страницу до и после нового ответа. Она нигде не добавляется;
  первый запрос B не содержит cursor A. После B «Показать ещё» использует
  только cursor B. Не запускать продолжение автоматически или дважды,
  пока оно уже выполняется. UI не пересортировывает результаты backend.
  Ошибка продолжения сохраняет уже загруженные строки и предлагает повтор
  именно этой страницы с её q/cursor, без замены списка первой страницей.
- **Возврат, CAT-020:** прогнать оба входа с одинаковой fixture; открыть
  не первую карточку после догрузки и вернуться. Сохранены query/страницы/ID
  и прокрутка, лишнего HTTP нет, поле снова доступно для продолжения ввода.
  Возврат не ставит фокус программно и не открывает мобильную клавиатуру.
  Навигация коррекции UI-027 и фото-повтор UI-028 сохраняют прежний смысл.

Vitest использует управляемые часы и отложенные ответы HTTP, настоящий React
компонент и события ввода/композиции. Реальные sleep не являются проверкой
точной границы 250 мс. Быстрый тест доказывает события, DOM, abort и состояние,
но не физическую мобильную клавиатуру или браузерную геометрию.
Отдельный браузерный проход проверяет ввод без submit, фокус/курсор, inline
загрузку/результаты, уточнение/очистку и возврат из карточки на мобильной ширине.
Mock HTTP в браузере не доказывает живой backend или качество ранжирования.

## Уровни проверки

| Уровень | Что доказывает | Что остаётся за границей |
|---|---|---|
| Быстрый Go/React | Валидация, HTTP-форма, DOM-атрибуты, состояния и переходы; маленькие синтетические записи | Mock store не доказывает PostgreSQL; mock HTTP не доказывает работающий backend; jsdom/CSS substring не доказывают геометрию |
| PostgreSQL интеграция | Транзакции, NULL, aliases, seed, повтор импорта и restore на отдельной тестовой БД | Не подтверждает импорт в постоянную БД и работу опубликованного сайта |
| Офлайн dry-run полного пакета | Валидация фактического пакета v2 без мутации БД | Не подтверждает транзакцию, browser UX или ML-качество |
| Браузер | Геометрия, currentSrc/network, DPR, lazy, клавиатура и настоящий History Back | Не подтверждает качество распознавания |

Длительности быстрых проверок фиксирует существующий runner. Свидетельства
уровней записываются отдельно. Успех только быстрых тестов означает именно
успех быстрых тестов; незапущенный браузер или PostgreSQL остаются незапущенными.
