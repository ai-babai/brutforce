# План проекта Vino

Это этапный план, а не свидетельство выполнения. Актуальные владельцы и статусы
находятся в `TASKS.md`, текущее состояние — в
`agents-os/memory/WORKING.md`.

## Стратегия

Сначала заморозить данные и оценку, затем доказать retrieval baseline на
реальных near-duplicate группах и только после этого строить пользовательский
срез. Любое усложнение модели должно улучшать заранее выбранные метрики на
неиспользованной для tuning выборке.

## Этап 0 — проектный контракт

- Нормализовать ТЗ, архитектурные границы и трассируемую приёмку.
- Настроить Agents OS, память, роли и правила данных.
- Подготовить каталоги и шаблоны для воспроизводимых проходов.

Выход: новый исполнитель начинает работу по `BOOTSTRAP.md`, не сканируя всё
дерево; следующий шаг однозначен.

## Этап 1 — приём и аудит данных

- Получить каталог и public field dataset без изменения исходников.
- Зафиксировать хеши, происхождение, права, схему, объём и качество.
- Построить устойчивое сопоставление `image_id → product_id → slug`.
- Выявить дубли, near-duplicate семейства, отсутствующие/повреждённые фото и
  дисбаланс условий съёмки.
- Заморозить train/validation/public-test split и untouched holdout.

Выход: валидированные манифесты, data audit и воспроизводимые splits без утечки.

## Этап 2 — измеримый baseline

- Реализовать детерминированную нормализацию и простой CV baseline.
- Построить индекс только по разрешённому каталожному набору.
- Выполнить top-1/top-5/F1/latency/error-analysis по frozen split.
- Добавить честный порог отказа для unknown/out-of-catalog.

Выход: первый воспроизводимый отчёт; ошибки разложены по near-duplicate группам
и условиям съёмки.

## Этап 3 — повышение достоверности

- Сравнить feature extractors и стратегии fine-tuning без изменения holdout.
- Исследовать crop/perspective/glare normalization.
- Добавить локальный reranker и только затем измерить пользу OCR.
- Калибровать confidence/margin и выбрать рабочую точку accuracy/coverage.

Выход: кандидат с доказанным улучшением над baseline и сохранённым протоколом.

## Этап 4 — вертикальный продуктовый срез

- Стабилизировать API-контракты поиска и карточки.
- Реализовать камера/галерея → поиск → карточка в mobile-first UI.
- Поддержать плоский endpoint для Bash-скрипта.
- Реализовать и проверить recovery/not-found состояния.

Выход: локальный end-to-end demo на frozen public наборе.

## Этап 5 — функция после поиска

- Выбрать функцию через короткую продуктовую оценку ценности, данных, риска и
  времени: сочетания, цифровой сомелье, подбор аналога или другая гипотеза.
- Зафиксировать отдельные acceptance criteria и не смешивать её метрики с
  качеством поиска.

Выход: одна работающая функция, повышающая полезность результата.

## Этап 6 — воспроизводимость и защита

- Docker/локальный запуск, фиксированные версии, one-command smoke.
- Полный public benchmark, SLA warm/cold, негативные и security tests.
- README, ARCHITECTURE, демонстрационный сценарий и 7-минутный питч.

Выход: зафиксированный release candidate с независимым QA verdict.
