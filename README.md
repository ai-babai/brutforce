# BrutForce — сканер российских вин

<p align="center">
  <img src="docs/product/readme-lct-2026.png" width="960" alt="Лидеры цифровой трансформации — 2026: РСХБ, команда Брютфорс и платформа «Своё Вино»">

Проект команды соревнования **«Лидеры цифровой трансформации — 2026»** по кейсу **Россельхозбанка (РСХБ)** для платформы «Своё Вино». Задача — по фотографии этикетки найти точную запись в каталоге российских вин и открыть её карточку на телефоне. Решение сочетает распознавание изображения, поиск по каталогу и мобильное веб-приложение. При отсутствии подтверждённой карточки приложение не выдаёт другое вино за точное совпадение.

**Два API:** для проверки по требованиям организаторов — [`POST https://app.dzap.pw/v1/eval/predict`](https://app.dzap.pw/v1/eval/predict) (фото в поле `image`, ответ со `slug`); для поиска в приложении — [`POST /v1/photos`](https://app.dzap.pw/v1/photos) (поле `photo`) → [`POST /v1/search`](https://app.dzap.pw/v1/search) (`photoId`, кандидаты для интерфейса). Это разные контракты; запрос для организаторов показан ниже.

**Авторы проекта:** Максим Попков ([Telegram @skifmax](https://t.me/skifmax)) и Роман Карандашов ([GitHub MisterMolox](https://github.com/MisterMolox)). [English](README.en.md).

## Быстрый запуск

Для распознавания этикетки нужны Linux x86-64, Docker с Compose v2 и [внешний комплект данных](https://disk.yandex.ru/d/dHAXDPcitS-ZJQ). Требования к памяти и диску — в [руководстве по запуску](docs/SELF-HOST.ru.md#полный-режим-с-docker). Клонируйте репозиторий:

```sh
git clone https://github.com/ai-babai/brutforce.git
cd brutforce
```

Скачайте все 14 файлов комплекта, проверьте SHA-256 и распакуйте их в `$HOME/brutforce-local` [по инструкции](docs/ASSET-TRANSFER.ru.md#как-восстановить-на-linux). Из корня клона выполните:

```sh
sh scripts/docker-local.sh init "$HOME/brutforce-local"
sh scripts/docker-local.sh up
sh scripts/docker-local.sh smoke
```

`init` создаёт локальную конфигурацию и пароли; `up` уже проверяет файлы и запускает полный Compose. Откройте <http://127.0.0.1:8097/>. Для остановки: `sh scripts/docker-local.sh stop` (данные в volumes сохраняются).

Нужен только интерфейс без модели? После клонирования выполните `docker compose -f deploy/compose.demo.yaml up --build -d --wait`. Это демо с восемью пробными карточками: **конкурсный API вернёт 503, а не результат распознавания**. [Другие способы запуска](docs/SELF-HOST.ru.md).

## Как подложить свои данные

Разместите распакованный комплект **вне Git** в одном каталоге:

```text
~/brutforce-local/
├── f8-bundle/                 веса, OCR, визуальный индекс и slug организаторов
├── catalog-package/           карточки витрины и manifest
├── catalog-media/             изображения карточек
└── recommendations/index.json отдельный индекс рекомендаций
```

Если используете другой путь, укажите его при **первом** `sh scripts/docker-local.sh init /absolute/path/to/data`. Скрипт подключит эти каталоги и создаст локальные секреты; `up` сверит зафиксированные версии и SHA. Произвольный новый каталог вин или папку с эталонными фото просто подставить нельзя: понадобятся согласованные визуальный индекс, список slug, пакет каталога и контрольные суммы. [Формат и ограничения](docs/SELF-HOST.ru.md#данные-для-полного-режима) · [пересборка индексов](docs/ASSET-TRANSFER.ru.md#как-заново-построить-индексы). Свои **фото для проверки** передавайте в запросе API ниже, не копируйте в каталог модели.

## Как вызвать конкурсный API

Для проверки работающего сервиса отправьте фото этикетки на **`https://app.dzap.pw/v1/eval/predict`** как **одно** multipart-поле `image`:

```sh
curl --fail-with-body --max-time 10 \
  -F 'image=@/path/to/your-label.jpg' \
  https://app.dzap.pw/v1/eval/predict
```

Для локального полного режима замените адрес на `http://127.0.0.1:8097/v1/eval/predict`. При подтверждённом совпадении ответ — HTTP 200 и `{"slug":"catalog-slug"}`. При `no_match` или `insufficient_information` API возвращает HTTP 200 с полем `action` вместо slug; техническая ошибка даёт другой статус, демо без модели — 503. Токен для локального API не нужен. Здесь используется `image`, **не** поле `photo` из пользовательского `/v1/photos`. [Формат, лимиты и ответы](contracts/eval-predict.md).

Для **приложения** используется другой путь: `POST /v1/photos` сохраняет фото и возвращает `id`, затем `POST /v1/search` с JSON `{"photoId":"полученный-id"}` выдаёт кандидатов для интерфейса. Поиск по названию идёт через `GET /v2/catalog?q=...`. [Интерактивная документация API](https://app.dzap.pw/api/docs) · [описание границ приложения](apps/api/README.md#boundary-and-contract).

## Краткая архитектура

```mermaid
flowchart LR
    web["Браузер · React"] --> api["Go API"]
    contest["Организатор · image"] --> api
    api -->|карточки и поиск по названию| catalog[(PostgreSQL · витрина)]
    api -->|поиск по фото| vision["CPU vision · модель и индекс"]
    vision -->|slug| api
    api -->|похожие карточки| recommendations[(Индекс рекомендаций)]
```

Приложение загружает фото через `/v1/photos` и ищет по `photoId` через `/v1/search`; если у slug нет карточки витрины, чужое вино не подставляется. Код CPU-сервиса — в [apps/vision/](apps/vision/README.md). [Полная схема](ARCHITECTURE.md).

## Исследования и проверки разработки

### Датасет и тестовые корзины

Для исследования поиска по этикетке собрали банк изображений по SKU и отдельные тестовые корзины для сравнения подходов.

- [Журнал экспериментов Романа](https://reps.roman.dzap.pw/#experiments) — протоколы и top-1/top-3/top-5 для validation и test.
- [Карта покрытия](https://reps.roman.dzap.pw/#coverage) — группы кандидатов и нехватка подтверждённых снимков по SKU.

> Скачанный кандидат ещё не является проверенным независимым референсом. Метрики экспериментов не равны конкурсной точности развёрнутого сервиса.

В [атласе референсов](https://reps.maks.dzap.pw/view#references) разобрали экраны винных приложений и пользовательские сценарии. [Сценарии и макет](https://reps.maks.dzap.pw/view#flows) показывают решения для мобильного веба. На снимке — макет с вымышленными данными, а не работающий сканер.

### Проверки поведения (BDD)

При разработке агентами фиксировали поведение API и состояния UI в сценариях, чтобы замечать регрессии между ревизиями. [Карта поведения](https://reps.maks.dzap.pw/behavior/) показывает статусы сценариев и историю прогонов. Быстрые проверки используют подменённый распознаватель и не измеряют качество поиска по фото.
