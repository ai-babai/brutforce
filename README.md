## Быстрый запуск

Этот проверяемый локальный путь запускает **синтетический демо-режим без F8**; для настоящего CPU F8 следуйте [runbook](docs/RUNBOOK.ru.md). Нужны Go 1.23, Node.js 22 и npm; PostgreSQL для синтетического режима не требуется.

В первом терминале из корня репозитория:

```sh
mkdir -p ./local-uploads
cd apps/api
UPLOAD_DIR="$(pwd)/../../local-uploads" go run .
```

Во втором терминале из корня репозитория:

```sh
cd apps/web
npm ci
npm run dev
```

Откройте <http://127.0.0.1:5190/>. Проверка процесса: `curl --fail http://127.0.0.1:8097/v1/health`. Для остановки нажмите Ctrl-C в обоих терминалах; удалите `local-uploads` только если его содержимое вам больше не нужно. Реальные загруженные снимки не публикуйте. `POST /v1/eval/predict` без F8 возвращает `503 recognition_unavailable` — это ожидаемо в локальном демо.

## Docker с реальной моделью

На Linux x86-64 с Docker Engine/Compose v2 получите от владельца **вне Git** проверенный F8 bundle ([50 SHA](deploy/assets/f8-cpu.sha256)), согласованный пакет каталога, его media и отдельный индекс рекомендаций. Настройте абсолютные пути в приватной копии [`deploy/docker.env.example`](deploy/docker.env.example), а два password-файла держите в `SECRETS_DIR` вне репозитория. [Полная пошаговая инструкция](docs/RUNBOOK.ru.md#полный-cpu-профиль-f8) описывает проверку/экспорт bundle, права и сохранение данных.

```sh
sh scripts/docker-local.sh preflight
sh scripts/docker-local.sh up
sh scripts/docker-local.sh smoke
sh scripts/docker-local.sh stop
```

`up` запускает отдельные PostgreSQL, migrator, F8 vision и web/API; после готовности приложение доступно на `http://127.0.0.1:8097`. `smoke` проверяет только HTTP, а не точность модели. Образы и clean-Linux end-to-end ещё не подтверждены; действующий PROD работает через systemd, не Docker.

## Система кратко

```text
браузер (React/TypeScript) → Go API ──→ PostgreSQL (карточки)
                                ├──→ приватные фото и feedback (вне web-root)
                                └──→ CPU F8 vision (отдельный сервис и assets вне Git)
```

Конкурсный endpoint возвращает только проверенный slug; приложение сопоставляет его с ID существующей карточки. Отдельный закреплённый индекс рекомендует карточки по тексту витрины и атрибутам винодельни, не гарантирует точный матч и не предсказывает вкус. [Полная схема](ARCHITECTURE.md).
