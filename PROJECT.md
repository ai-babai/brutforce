# Проект Vino: сканер российских вин

Статус: подготовка данных; исходное ТЗ нормализовано 2026-09-11. При конфликте
формулировок проверять локальный закрытый источник `10. РСХБ.Цифра.pdf`, который
намеренно не хранится в Git.

## Цель

Создать встраиваемый в каталог «Своё Вино» mobile-first веб-модуль, который по
фотографии этикетки российского вина находит одну соответствующую позицию и
показывает её карточку. Основной бизнес-результат — достоверное распознавание в
реальных условиях у полки и полезный сценарий после поиска.

## Обязательный пользовательский сценарий

1. Пользователь снимает этикетку камерой телефона или выбирает фото из галереи.
2. Сервис валидирует и нормализует изображение.
3. CV-поиск сравнивает изображение с каталогом.
4. В пределах целевого SLA сервис возвращает один лучший `slug` либо честный
   результат отсутствия позиции; экран выбора из похожих вариантов не является
   целевым UX.
5. Фронтенд открывает карточку найденного вина: производитель, регион, сорт,
   описание, рейтинг Роскачества и рекомендация по сочетанию.
6. После поиска доступна дополнительная функция, повышающая полезность и
   удержание; её вид должен быть выбран и проверен отдельно.

## Функциональные требования

- Ввод: фотография этикетки из камеры или галереи в веб-интерфейсе.
- Поиск по изображению обязателен; OCR допускается как дополнительный сигнал.
- Каталог содержит ориентировочно 1500–2000 позиций и одну эталонную фотографию
  на позицию; множество near-duplicate этикеток является главным риском.
- Приблизительный прирост каталога — 50 наименований в день; мгновенная
  переиндексация не требуется.
- Результат приложения содержит карточку вина в формате JSON для фронтенда.
- Контрольный Bash-скрипт ожидает ровно один лучший результат в плоском JSON:
  `{"slug":"wine-slug"}` для каждого изображения.
- Вне каталога: допускается показать похожие вина/аналоги только как отдельно
  обозначенный сценарий; всегда допустим честный `not_found`.
- Для каждого запроса должны быть доступны top-1/top-5 диагностические метрики
  уверенности, не нарушающие плоский контракт оценочного endpoint.
- Отдельное нативное мобильное приложение не требуется.

## Данные и оценка

- Кейсодержатель предоставляет дамп каталога JSON и публичный набор полевых
  фотографий; закрытый набор используется в онлайн-защите.
- Точные форматы и объёмы ресурсов должны быть проверены при получении.
- Целевой ориентир ТЗ: 90–100% совпадений на контрольной выборке; фундаментальна
  достоверность, затем стабильный F1 и заметный отрыв top-1 от top-2.
- Скорость оценивается как плюс при целевом времени ответа до 3 секунд, но имеет
  меньший вес, чем достоверность.
- Оценка должна отдельно показывать public и untouched holdout, near-duplicate
  группы, неизвестные позиции, качество по условиям съёмки и latency.
- Помимо closed-set каталога поддерживается open-world библиотека российских
  вин. Она хранит будущие позиции каталога, прошлые винтажи и поколения дизайна;
  отсутствие текущего `slug` «Своё Вино» не является причиной удалить объект.
- Ребрендинг, смена года, объёма или деталей этикетки моделируются отдельными
  variant/design ID внутри одного wine family и используются как hard cases.

## Программно-аппаратные рамки

- Основной сценарий рассчитан на GPU. CPU-режим допустим как диагностический или
  отдельный baseline и оценивается экспертами отдельно.
- Команда самостоятельно обеспечивает обучение, дообучение и inference на
  собственном GPU либо через внешних API-провайдеров.
- Допустимы открытые веса и закрытые API; специальных требований к лицензиям
  моделей и реестру российского ПО в ТЗ нет. Права на сами данные всё равно
  должны быть подтверждены.
- Обязателен CV-компонент поиска по изображению.
- Nuxt, PostgreSQL + pgvector, SigLIP 2, Strapi OSS и Docker указаны как
  рекомендуемый стек, а не как обязательный контракт.
- Демонстрация выполняется локально на компьютере команды; внешний deploy не
  требуется.

## Требования к сдаче

- Открытый репозиторий для экспертов и зафиксированная версия финала.
- Воспроизводимые setup/start/config или Docker-инструкции.
- Работающий end-to-end: загрузка фото → поиск → JSON/карточка.
- Mobile-first карточка в стилистике «Своё Вино».
- Результаты public benchmark: top-1, top-5, F1 и latency.
- Совместимость с оценочным скриптом кейсодержателя.
- `README.md` с запуском, переменными окружения и ограничениями.
- `ARCHITECTURE.md` с границами normalization, feature extraction, retrieval,
  reranking/confidence, выдачи карточки и дополнительной функции.
- Питч до 7 минут: концепция, pipeline, live demo, метрики, дополнительная
  функция и выводы.

## Приоритеты оценки

1. Достоверность поиска — 50/100.
2. Функция после поиска — 20/100.
3. Архитектура и воспроизводимость — 15/100.
4. Дизайн — 10/100.
5. Скорость — 5/100.

## Зафиксированные границы текущего этапа

Девять полученных семейств raw-источников зарегистрированы; item-level manifests
и quality audits построены. Текущий wine sitemap «Своё Вино» обработан целиком,
шесть внешних наборов проверены по российскому покрытию и применимости.

Дополнительно зарегистрированы семь retail web-sources для open-world
библиотеки. Разрешённые snapshots МАВТ, «Ароматного Мира» и Алкотеки полностью
собраны и проаудированы; «Красное&Белое», ВинЛаб, SimpleWine и LUDING остановлены
после 401/403 без обхода защиты, для продолжения нужен официальный export или
разрешение. Frozen splits не выпущены до закрытия identity, annotation и
near-duplicate очередей. Стек, модель, пороги уверенности и дополнительная
функция не приняты.
