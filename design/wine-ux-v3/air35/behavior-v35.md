# Air 3.5 — BDD addendum и карта проверок

Дата: 25.09.2026. Основание: текущее уточнение Макса. Уточнения пользователя приняты для продуктовой ветки Sigma; этот документ не является свидетельством работающего сервиса.

`AIR-024` заменяет прежнее требование «180 px / не более 390 px»: оно закрепляет уменьшенный видоискатель вопреки запросу. Видео занимает доступный экран камеры; текст и controls могут быть наложены поверх с контрастным градиентом. `AIR-025–029` новые сценарии. `AIR-001–023`, включая отмену галереи, гонки запросов, различение пустого ответа/ошибки/сети, повтор по receipt, Back, сохранённое, IME и пагинацию, остаются в силе. Текст Gherkin — [behavior-v35.feature](behavior-v35.feature).

| Сценарий | Продуктовая проверка | Среда/браузер |
| --- | --- | --- |
| AIR-024 | React: `getUserMedia`, реальный video, кадр из потока, остановка current/late stream; отказ разрешения оставляет галерею. Изменить прежние точные CSS substring проверки `design.test.tsx` DESIGN-008/010/011/012/016, сохранив safe area, landscape и desktop shell. | Playwright: 320×640, 430×932, 844×390; видео заполняет доступный экран камеры, controls могут быть overlay, видимы и кликабельны; градиент сохраняет контраст, нет overflow. Не закреплять video отдельной карточкой над controls. Отдельный визуальный снимок с подменённым MediaStream. |
| AIR-025 | React с управляемыми ответами: `File` → ровно один upload → receipt → search; успешные 1/несколько/0 кандидатов, 503, transport error, malformed response; retry без второго upload; поздние ответы после замены/отмены игнорируются. Не подменять поиском текста. | На Maks: проверка фактических `/v1/photos`, `/v1/search`, внутреннего `/v1/search/image` и конфигурации хранилища/сервиса с безопасным тестовым изображением и известным receipt. Фиксировать HTTP-коды и request ID без фото/секретов в отчёте. Синтетика доказывает путь, не качество ML. |
| AIR-026 | DOM: первый кандидат по порядку API, только он отмечен лидером, клик открывает его ID; остальные, singleton и Back сохраняют старые гарантии. | Геометрия в браузере: фоновая полоса `left≈0`, `right≈clientWidth` внутреннего viewport (допуск 1 CSS px), без видимой границы на 320/430 и desktop frame. Содержимое остаётся в безопасных внутренних отступах; screenshot review. |
| AIR-027 | Переходы Home→Search→Saved→Home и быстрая смена: один индикатор, финальный selected/`aria-current` и раздел совпадают. CSS-токен можно тестировать как источник, но результат доказывает computed style. |
| AIR-029 | DOM: на Главной нет отдельной подсказки «Этикетка целиком, нужная бутылка по центру» и её смыслового дубля; камера сохраняет свою подсказку. Основная CTA и парные входы остаются рабочими без нового onboarding. | Визуальная проверка Главной на обычной и короткой динамической высоте: маскот чуть крупнее, действия ниже единой группой; цели 48+ CSS px, safe area и отсутствие перекрытий. Не фиксировать произвольные пиксели пропорций. |

Регистрация: добавить `AIR-024–029` в источник feature, `cases/cases.json` и маппинг fast/report как отдельные свидетельства. Не отмечать сценарий зелёным по существованию CSS-селектора или одному unit mock. Для `AIR-025` уровень deployed smoke должен показывать работоспособность именно среды Maks; локальный Go reference/mock и ручной текстовый поиск не заменяют его. Старые отчёты остаются историей.
