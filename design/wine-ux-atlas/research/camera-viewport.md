# Камера: доступная высота вкладки — draft 3.6

19.09.2026. Основание: реальные Android / Яндекс Браузер скриншоты пользователя. При открытых нижних панелях затвор находился за видимой областью; при скрытых появлялся. Подсказка была обрезана слева. Самих пользовательских фото в репозитории нет.

## Что изменено в макете

Камера занимает видимую область вкладки как отдельный слой; Fullscreen API не вызывается. При закрытии возвращается обычный макет. Убраны фиксированные 690/724 px и min-height:390px превью в режиме камеры. Новая сетка: toolbar / minmax(0,1fr) превью / подсказка / действия. Сжимается только превью. Прокрутка фона блокируется на время камеры.

Высота: CSS 100vh → 100dvh; JS custom property --camera-viewport-height обновляется из visualViewport.height (fallback innerHeight) на resize окна и visualViewport. Это текущая доступная высота, не screen.height и не outerHeight. Не вычитать высоту панелей браузера вручную: она уже учитывается viewport и отличается по устройствам.

safe-area: верх max(4px, env(safe-area-inset-top)), низ max(8px, env(safe-area-inset-bottom)), стороны max(12px, env(safe-area-inset-left/right)). border-box; viewport-fit=cover. Не отключать пользовательское масштабирование.

Затвор 66×66 px; остальные действия минимум 48×48 px. Камера, галерея, закрытие и подсказка о свете доступны без скролла при штатном масштабе. Подсказка «Нужная бутылка по центру» находится отдельной полосой ПОД изображением и рамкой, перед действиями (в landscape — под превью, слева от действий): position:static, без translate, max-width:100%, перенос слов допустим. При смене на совет убрать блик строка может увеличиваться, за счёт превью.

При высоте ≤480 px gap уменьшается с 8 до 4 px и скрывается только вторичная подпись под затвором. Основная подсказка и действия остаются. Landscape при высоте ≤600 px: сетка minmax(0,1fr) 88px; действия справа, затвор и галерея друг под другом. Визир inset 12 px. Демофото вписано целиком; в реальном video object-fit:cover допустим при согласованности отображённого кадра и захвата — данный макет не реализует видеопоток.

## Given / When / Then для переноса

| Given | When | Then |
|---|---|---|
| Обычная вкладка Android, нижняя панель открыта | Вход в камеру | Затвор, галерея, закрытие и подсказка видны без скролла; Fullscreen API не нужен. |
| Камера активна | Панели браузера скрываются / возвращаются | Меняется высота превью, действия остаются внутри visual viewport; фото/поток не сбрасываются. |
| Камера активна | Поворот portrait → landscape → portrait | Действия перестраиваются вправо и обратно; не требуется повторно запускать камеру. |
| Узкий экран / длинная подсказка | Показ подсказки о свете | Текст целиком внутри горизонтальных отступов, допустим перенос; затвор не вытесняется. |
| Standalone PWA с системной панелью / вырезом | Вход и поворот | Те же действия доступны; safe-area предотвращает перекрытие; отсутствие браузерной панели не меняет логику. |
| Fullscreen недоступен / пользователь отказал | Съёмка | Основной путь продолжает работать. Не просить скрывать панели или устанавливать PWA. |
| Камера активна | Закрытие / галерея / затвор | Слой камеры снимается; соответствующий следующий экран и прокрутка доступны. |

Нижний брендовый footer не должен занимать место в camera route. Не масштабировать всю страницу, чтобы уместить элементы. В standalone не добавлять искусственный отступ под отсутствующую панель браузера.

## Проверка и ограничения

Локальный браузер: 360×560 (визуальная проверка), 360×740 → 360×480 (изменение высоты без перезапуска), 640×320 (визуально), 640×280. Затвор целиком в viewport, подсказка не выходит за горизонтальные границы; previewHeight остаётся положительным. Проверен выход из камеры. node --check прошёл.

Это имитация доступных CSS-размеров, не тест настоящего Яндекс Браузера. Реальные панели, ненулевые safe-area, standalone PWA и увеличенный системный шрифт нужно проверить на устройстве после переноса. Для крайне малой высоты при крупном шрифте нельзя обещать размещение любого объёма текста без дополнительной адаптации; основные действия имеют приоритет. Не считать скриншоты устройства точными CSS-пикселями.

## Уточнение по второму скриншоту — draft2

Подсказка не является overlay внутри video/preview: DOM-порядок toolbar → preview → guidance → actions. Рамка — абсолютный дочерний элемент preview с inset 12 px; guidance — следующий sibling в auto-строке. Между preview и guidance gap 8 px, при коротком экране 4 px. Guidance padding 4px 8px, line-height 1.4; строка может переноситься, уменьшает только preview, не высоту затвора. В landscape строки auto / minmax(0,1fr) / auto, guidance в третьей строке первой колонки, действия справа во второй/третьей строках.

«Выбрать фото»: белая иконка 22 px и подпись 11px/500 на #352e36, кнопка шириной 88 px, минимум 48 px высотой; обводка #857780. Цвет ссылки/акцента #742c46 для этой подписи запрещён на тёмном фоне камеры. Focus outline белый 2 px. На ≤340 px gap между действиями 10 вместо 16 px. Размер затвора остаётся 66 px.

Дополнительные критерии:
- Given камера с открытыми панелями браузера; When показана подсказка; Then guidance.top ≥ preview.bottom + gap, а рамка целиком внутри preview. Никакого пересечения даже с нижней линией рамки.
- Given короткая высота 360×480 или landscape 640×280; When подсказка о свете переносится; Then затвор полностью виден и не уменьшается, сжимается превью.
- Given тёмный кадр; When видна галерея; Then иконка и текст «Выбрать фото» читаемы независимо от видеокадра (непрозрачный фон кнопки).
