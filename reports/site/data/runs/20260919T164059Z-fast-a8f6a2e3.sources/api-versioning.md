# Версии API

## Сейчас

До добавления OpenAPI API имел историю в Git, но не номер публичного контракта.
Существующие `/api/health`, `/api/catalog`, `/api/photos`, `/api/search` —
неверсионированные адреса демо. Они сохраняются для работающего приложения.

Первая документированная версия демо-контракта — `0.1.0` в `info.version`
OpenAPI. По нашей конвенции это версия описанного контракта; она не равна
версии формата OpenAPI (`openapi: 3.1.0`) или релизу приложения.
Точный код реализации и тестов определяется Git SHA релиза.

## Правило изменений

- Правка описания без изменения поведения: patch (`0.1.1`).
- Совместимое расширение контракта: minor (`0.2.0`).
- Удаление/переименование поля, новый обязательный параметр или изменение
  смысла результата — несовместимое изменение. Его явно согласовываем и
  обновляем потребителей вместе; номер `0.x` не разрешает незаметно ломать UI.
- Конкурсный `POST /v1/eval/predict` — планируемый отдельный контракт версии
  `v1`, а не псевдоним синтетического поиска. В доступных методах документации
  он появляется только после реализации. Для будущих несовместимых изменений
  стабильного контракта используем новый major-путь, например `/v2/...`.
- Версия пути — основной механизм выбора стабильного API. Не добавляем
  обязательные version-заголовки, query-параметры или поле версии в каждый
  ответ: клиент организаторов их не отправляет и читает только `slug`.
- Конкурсная совместимость проверяется отдельно от демо: собственные
  сценарии запросов/ответов и прогон неизменённого `participant_test.sh`.
  Зелёные тесты `/api/search` или документации не означают готовность `/v1/eval/predict`.
- Каждый реализованный контракт, сценарии и проверки коммитятся и отправляются
  в GitHub. Старые прогоны отчёта сохраняются. Номер версии сам по себе не
  доказывает совместимость — её проверяют тесты запросов и ответов.

Документация: `/api/docs`. Она показывает текущую реализацию, а не все
исторические версии сервиса. Исходные версии доступны в Git.
