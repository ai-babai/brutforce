## Уточнения сценариев для реализации

Это проверяемые уточнения уже порученного поведения, а не новые продуктовые функции.

1. **CAT-001:** дано 73 канонических синтетических записи и aliases; GET без limit
   возвращает 24, продолжение возвращает остальные по slug ровно один раз,
   финальная страница не содержит cursor; 0, 61 и нечисловой limit отклоняются.
   Cursor предыдущего query или версии отклоняется явно.
2. **CAT-002:** дано искомое вино вне первой страницы; ввод с главной через
   «По названию» и ввод после открытия каталога обращаются к одному каталожному
   GET с q; ответ содержит искомое. Смена q очищает cursor, поздняя страница
   старого q не добавляется, пустой ответ и ошибка с повтором различимы.
3. **CAT-004/005:** дано unknown year/volume, invalid alcohol и отдельный
   корректный диапазон; сериализация/карточка не содержат 0/NaN, диапазон
   остаётся диапазоном. Три спорные синтетические проекции сохраняют только
   согласованные color/sweetness; raw category и догадки отсутствуют.
4. **CAT-006:** три aliases разрешаются в canonical ID; список и поиск
   содержат canonical один раз; неизвестный slug даёт JSON 404. Проверить
   PostgreSQL lookup отдельно от `displayCatalog.Resolve`, где alias задан вручную.
5. **CAT-007:** reference-поиск по фото возвращает настоящую карточку;
   источник/дата настоящие, распознавание явно обозначено как заглушка,
   карточка не названа синтетической. Самостоятельное открытие каталога
   не получает утверждений об успешном распознавании.
6. **CAT-008/009:** импорт A → полный snapshot → dry-run B/ошибка B → snapshot
   равен A; ошибка после начала записи также сохраняет A. Успех B → повтор B
   не меняет содержимое; seed/migrate не добавляют demo-записи и сохраняют
   NULL year/aliases; восстановление A проверяется повторным чтением.
7. **REPORT:** одна граница падает, другая того же ID проходит → сценарий
   failed с обоими свидетельствами. Два ID в названии → оба учтены.
   Незапущенная обязательная интеграция/браузерная проверка остаётся незапущенной.
8. **CAT-003/SR-009:** отдельный браузерный проход 320/390/desktop, DPR 1/2/3,
   увеличенный текст, currentSrc/network и геометрия. Быстрый тест проверяет
   только реальные DOM-атрибуты, fallback и переходы.

Старые UI-027 (возврат/контекст), UI-028 (различимые ошибки/receipt),
SR-001…006 (выбор/порядок/Back) сохраняют продуктовую ценность.
Замена транспорта не разрешает удалять их assertions ради зелёного прогона.
SVC HTTP mock доказывает адаптер; EVAL с injected recognizer доказывает
конкурсную границу; ни один не доказывает качество модели. DB-тесты на
настоящем PostgreSQL дают отдельное свидетельство и не заменяются mocks.

### Дополнительные конкретные остатки

- **P1, импорт:** `internal/catalogimport/import.go`, `validateImage`: пустой
  `Path` возвращает успех до проверки полноты v2. Синтетический пакет с
  тремя объектами `{role: thumbnail/card/original}` без путей, размеров и
  файлов принят CLI с `-version audit-v2 -dry-run` (exit 0, одна запись).
  Получается формально импортируемая запись с невалидными imageVariants.
  Пустые названные variants должны отклоняться. Если разрешена карточка без
  изображения, она должна оставаться без выдуманных пустых variants.
- **P2, embedded API:** `catalog_store.go:70` не проверяет ExpectedVersion
  в `embeddedCatalogStore.Page`; PostgreSQL проверяет её. Поэтому stale-cursor
  контракт не покрыт одинаково во всех режимах. Текущий stale-тест использует
  подменённый store и не обнаруживает этот путь.

В повторном аудите только минимальный отсутствующий-image package был
запущен через реальный CLI; временный каталог удалён. Постоянная БД и live
не затрагивались. Закрытие указанных остатков требует итогового diff.

  `image: null` обрабатывается отдельно; пустые named variants не создаются.

  HTTP-тест добавлены. **Symlink-проверка усилена:** внешний target теперь
