# Каталог и сохранённое

Производитель: Go API; потребитель: React UI. При настроенном `DATABASE_URL` каталог читается из PostgreSQL; `apps/api/catalog.json` задаёт синтетический seed и автономный режим быстрых тестов. Схема и ограничения — [database.md](database.md). Ошибка настроенной БД не включает автоматический JSON fallback. Поля записи соответствуют `demo-search.schema.json`.

`GET /v2/catalog` возвращает ограниченную страницу с `catalogVersion` и необязательным `nextCursor`.
Полный контракт пагинации, реальных карточек и aliases — [catalog-display.md](catalog-display.md).
По умолчанию 24 карточки, максимум 60; интерфейс догружает их через «Показать ещё».
Ручной поиск выполняется по всему каталогу на сервере, а не по уже загруженной странице.

Без импорта используются восемь синтетических записей (`demo: true`). После проверенного
импорта возвращаются реальные каталожные факты (`demo: false`); это не означает реального
распознавания фотографий. Происхождение карточки и режим распознавания обозначаются отдельно.
Неизвестные год и атрибуты отсутствуют, источник и дата сохраняются в карточке.
Сохранённые снимки не меняются самопроизвольно при выпуске новой версии каталога.


Сохранённое — локальный список снимков карточек в браузере. Сохраняется после перезагрузки на этом устройстве, не синхронизируется между людьми/браузерами. Фото пользователя не копируются в этот список. Удаление записи не удаляет оригиналы фото на сервере. При запрете записи storage интерфейс сообщает, что постоянное сохранение не удалось. Повреждённая запись не должна ломать запуск приложения.

Установка PWA не обязательна. Поиск/каталог используют тот же API в обоих режимах. Offline-каталог, общий аккаунт и совместное избранное вне текущего объёма.
