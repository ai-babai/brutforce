# Security Specs · публичное демо

Инициатор: Макс, 19.09.2026. Цель — ограничить расходы сервера на недоверенный ввод и не принимать невалидные фотографии. Это минимальная прикладная защита, не сертификат безопасности.

## Правила и быстрые проверки

| ID | Дано / Когда | Тогда |
|---|---|---|
| SEC-001 | ZIP или SVG назван картинкой и отправлен как photo | 400, никаких файлов в хранилище; расширению и клиентскому MIME не доверяем |
| SEC-002 | Правильный PNG-заголовок, но оборванные пиксели | Декодирование не проходит, 400 без записи |
| SEC-003 | Маленький файл заявляет >25 млн пикселей или сторону >12000 | Отказ до декодирования пикселей; умножение размеров не переполняется |
| SEC-004 | >10 MiB файла, лишнее поле или несколько файлов | Отказ; тело multipart ограничено 11 MiB; никаких файлов на диске |
| SEC-005 | Две загрузки уже обрабатываются | Третья получает 429 + Retry-After без чтения тела; после завершения слот освобождается |
| SEC-006 | Поисковый текст длиннее256 символов, управляющие символы, невалидный UTF-8/JSON, >64 KiB | 400; корректный текст рассматривается как данные, не SQL/HTML/команды |
| SEC-007 | Превышен бюджет POST, сжатое тело, неподходящий MIME поиска или чужой Origin | 429/415/403 до обработчика; бюджет восстанавливается со временем |
| SEC-008 | Запрос публичного доступа к приватному файлу/подмена photoId путём | Содержимое не выдаётся; ответы имеют nosniff, DENY и same-origin referrer policy |

## Конкретные бюджеты

- Файл JPEG/PNG/GIF: 10 MiB; 25 млн пикселей; сторона12000. Сначала DecodeConfig, затем Decode и сравнение размеров.
- GIF: декодируется только первый кадр, никогда DecodeAll. Оригинал может содержать дополнительные кадры/метаданные/хвостовые данные. Они не считаются проверенными и не выдаются публично. Если появится обработчик OCR/превью, он обязан применять те же лимиты, а публичную картинку создавать заново из декодированных пикселей.
- Одновременно максимум2 загрузки, включая чтение и декодирование. Общий бюджет загрузок12/мин с начальным запасом4; поиска60/мин с запасом10. Бюджеты общие на процесс, не по IP, X-Forwarded-For не позволяет их обойти. При перезапуске бюджет сбрасывается. Один активный посетитель может временно исчерпать общий бюджет: для демо это осознанное ограничение.
- JSON64 KiB, query256 Unicode-символов. Content-Type application/json. Content-Encoding, кроме identity, не поддерживается; архивы вообще не распаковываются.
- Хранилище200 MiB: оригиналы вне web-root, случайные имена,0600/0700, без выдачи/list endpoint. При заполнении503 без автоудаления.
- HTTP: заголовки16 KiB, ReadHeaderTimeout5s, Read/WriteTimeout10s. Служба ограничена MemoryMax1G, CPUQuota100% одного ядра, TasksMax64; остальные сервисы не должны делить с ней неограниченные ресурсы.

## Что доказываем

Go httptest вызывает настоящий обработчик с небольшими синтетическими вредоносными входами. Большие размеры изображения представлены33-байтовым заголовком, без гигантского файла и без нагрузки на публичный сервер. Конкурентность проверяется каналами, время rate-limit подменяется часами, без sleep. Отдельно go test -race для Security. Исполняемые проверки не моделируют объёмную DDoS-атаку, все уязвимости декодеров или вредоносность содержимого. Это не антивирус. HTTP timeouts не останавливают уже запущенное CPU-декодирование; внешние лимиты службы — дополнительная граница.

Основной прогон и длительности — в общей карте отчёта, раздел Security. Нагрузочные атаки на публичный сайт не проводим. Потребуются обновления Go и пересмотр лимитов при подключении ML/реальных пользователей.

## Основания

- [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html): несколько независимых проверок, размер и хранение вне web-root.
- [Go Security Decisions](https://go.dev/doc/security/decisions): размеры недоверенной картинки проверяются до Decode.
- [OWASP DoS](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html): ограничивать расход ресурсов и размер входа.
