# PostgreSQL: каталог демо

Область BE-031. Инициатор Макс; первая реализация — синтетический каталог, без импорта конкурсных данных.

## Граница

Go API читает восемь тестовых карточек из PostgreSQL, когда задан `DATABASE_URL`.
HTTP-контракт `/v1/catalog` и `/v1/search` не меняется. SQL-миграции и начальное наполнение
запускаются явно ролью миграций. Приложение не меняет схему при старте.
`catalog.json` — версия синтетического seed и источник автономного режима быстрых тестов.
Если PostgreSQL явно настроен, ошибка подключения не переключает приложение на встроенный каталог.

Файлы фото и квитанции остаются в приватном файловом хранилище. «Сохранённое» остаётся
локальным списком браузера. Общие аккаунты, синхронизация избранного, хранение оригиналов фото
в SQL, реальный ML и полнотекстовый поиск не входят в эту итерацию.

## Исполняемые сценарии

| ID | Дано | Когда | Тогда |
|---|---|---|---|
| DB-001 | Пустая зарегистрированная тестовая схема | Применены миграции Goose | Создана рабочая схема; повторное применение безопасно и сохраняет имеющиеся записи |
| DB-002 | Малый синтетический seed | Начальное наполнение применено повторно | По одному экземпляру каждого ID; уже изменённые значения не перезаписаны |
| DB-003 | Каталог в PostgreSQL | Чтение и ручной поиск через реальный Go API | Стабильные ID и поля, корректный пустой результат; SQL-подобный ввод остаётся данными |
| DB-004 | Данные записаны | Клиент закрыт и подключён заново | Данные сохранились, это не память процесса |
| DB-005 | Подключение runtime-роли | Чтение каталога и попытка DDL | Чтение разрешено, изменение схемы запрещено |
| DB-006 | БД недоступна при запросе | Клиент читает каталог или ищет вино | Структурированный HTTP 503 без DSN/пароля и без ложного успешного fallback |

При первой схеме нет предыдущего продуктового релиза для проверки upgrade. Проверяем установку
с нуля и повторное применение с сохранностью данных. При появлении второй миграции добавляем
настоящий переход v1 → v2; повторный запуск v1 не называем проверкой такого перехода.

## Быстрые проверки

- Обычный Go/Vitest прогон не зависит от запущенной БД. DB-006 проверяет обработку отказа
  через подмену только границы хранилища; это не доказательство исправности PostgreSQL.
- DB-001…005 запускаются отдельным коротким набором на настоящем PostgreSQL 18 через
  `lct-db-test maks`. Малый seed, одна база на набор, без установки сервера или полного импорта.
- В отчёте время БД и время локальных быстрых тестов показываются отдельно. Не выполненная
  интеграция — `not_run`, а не зелёный тест. Свидетельство БД связано с проверенной Git-ревизией.
- Временная схема сбрасывается только зарегистрированным инструментом. Постоянную `lct_maks`
  и данные других зон не очищаем. Все значения подключений остаются в защищённых env-файлах.
