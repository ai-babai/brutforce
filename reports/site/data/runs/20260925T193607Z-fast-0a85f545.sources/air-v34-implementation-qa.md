# Air 3.4 · локальная проверка реализации

Дата: 25.09.2026. Ветка: `codex/air-v34-implementation`. Площадка `demo.maks.dzap.pw` на момент этой записи ещё не обновлена.

## Быстрые проверки

- Web: 163 Vitest-проверки прошли после добавления самостоятельных Air-сценариев; production build собран до этого дополнения (исходники приложения не менялись).
- API: `go test -count=1 ./...` прошёл, включая обход 2038 синтетических записей каталога страницами по 24. Этот тест подтверждает ограниченный HTTP-ответ и порядок курсоров; он не измеряет выборку PostgreSQL без полной материализации.
- Последний [снимок fast report](../../../reports/site/data/index.json) имеет статус `partial` и прошёл за 7,84 с. Из Air без быстрого свидетельства остались только AIR-021 и AIR-024: доступность при увеличенном тексте и геометрия камеры требуют браузерной проверки. Ещё 18 исторических `DESIGN-*` проверяют старый v2 CSS и честно помечены как пропущенные. В этом локальном прогоне отдельное DB-свидетельство не предоставлено; в release CI оно обязательно. Время каждого теста доступно в отчёте.

До полной проверки AIR-021/AIR-024 и замены старых `DESIGN-*` выпуск ограничен preview Макса. В CI точные исключения перечислены в `deploy/fast-report-exceptions.json`; общий контроллер TEST/PROD отвергает пакет с `bddCoverageStatus: partial`. Публикация preview не является приёмкой доступности на реальном Android/iPhone.

## Браузерный просмотр

С локальной Vite-сборки просмотрены 11 состояний на 430×932 с подменёнными ответами API: главная, камера, ожидание, долгое ожидание, фото-выдача, карточка, ничего не найдено, ошибка сервера, отсутствие сети, ручной поиск и сохранённое. Ошибок JavaScript и горизонтального переполнения не было. Это проверка UI, не тест качества распознавания.

После правки камеры проверена геометрия на 320×640, 360×740, 390×850, 430×932 и 1440×900. На всех размерах нет горизонтального переполнения; кнопка «Сделать снимок» находится выше нижней навигации. Высота видоискателя по порядку: 180, 200, 310, 390 и 360 CSS px. На широком экране используется рамка телефона.

Независимая визуальная сверка с утверждённым макетом завершена дизайн-сессией с привлечением GPT-6 Sol: по 12 актуальным снимкам 430×932 блокирующих обрезаний и наложений нет. Её замечания о маскоте серверной ошибки, видимости фото после декодирования, нижней навигации, поиске и пустом сохранённом исправлены; разрешена публикация только на Maks. Проверка на реальном iPhone/Android, нативного выбора файла и живого ML-ответа остаётся отдельным этапом; локальная браузерная подмена этого не доказывает.
