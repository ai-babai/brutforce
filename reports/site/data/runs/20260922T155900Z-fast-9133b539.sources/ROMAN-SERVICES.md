## Что реализовать

1. Прочитай [поведение](../../contracts/wine-services.md) и
   [OpenAPI1.0.0](../../contracts/wine-services.openapi.json).
2. Реализуй поиск по фото и по тексту; отдельно — альтернативы известному вину.
3. Возвращай ID из согласованного каталога, score и версии модели/каталога.

   Язык/ML-стек выбирай под задачу. HTTP-контракт важнее внутреннего устройства.

## Входные данные

Для первого запуска используется `demo-v1`: восемь записей
[apps/api/catalog.json](../../apps/api/catalog.json). Это тестовый контрактный набор,
не датасет организаторов и не основание заявлять качество ML.

При переходе на реальный каталог сначала согласуй версию и точное соответствие ID/slug,
импорт в каталог приложения и индекс. Не заменяй строки DEMO реальными фактами молча.
Конкурсный `/v1/eval/predict` — отдельная спецификация; не подключай к нему заглушку.

## Запуск эталона локально

Из корня рабочей копии:

```bash
cd apps/api
go run ./cmd/reference-engine
```

По умолчанию эталон слушает только `127.0.0.1:8101`.
В другом терминале запусти наш API с двумя явно заданными адресами:

```bash
cd apps/api
SEARCH_SERVICE_URL=http://127.0.0.1:8101 \
RECOMMENDATION_SERVICE_URL=http://127.0.0.1:8101 \
CATALOG_VERSION=demo-v1 ADDRESS=127.0.0.1:8098 go run .
```

Без DATABASE_URL используется тот же встроенный синтетический каталог. Это удобный
автономный запуск для контракта, не fallback при ошибке настроенной БД.
Для загрузки фото через приложение дополнительно задай UPLOAD_DIR — приватную папку вне Git;
без неё API-only пример проверяет текст/рекомендации, а фото проверяются напрямую командой совместимости.
На сервере DATABASE_URL бери из защищённого env своей зоны (см. DATABASE.md), не из Git.
Не указывай WEB_ROOT для API-only проверки; UI можно запускать отдельно через штатный Vite.

Примеры прямых вызовов эталона:

```bash
curl --fail-with-body http://127.0.0.1:8101/v1/search/text \
  -H 'Content-Type: application/json' \
  -d '{"query":"Каберне","catalogVersion":"demo-v1","limit":3}'
curl --fail-with-body http://127.0.0.1:8101/v1/recommendations \
  -H 'Content-Type: application/json' \
  -d '{"wineId":"demo-cabernet-sauvignon-2023","catalogVersion":"demo-v1","limit":3}'
# Подставь путь к разрешённой тестовой картинке; не отправляй исходные данные наружу.
curl --fail-with-body http://127.0.0.1:8101/v1/search/image \
  -F image=@/path/to/test.png -F catalogVersion=demo-v1 -F limit=3
```

Эталон детерминированный: фото не распознаёт, возвращает синтетический ответ.
Проверки формы/ошибок/отмены не подтверждают качество рекомендации или распознавания.

## Проверки под твою реализацию

Быстрые тесты адаптера, эталона и UI не требуют модели или PostgreSQL:

```bash
# Из корня репозитория:
(cd apps/api && go test -count=1 -run '^TestSVC' ./...)
npm --prefix apps/web test -- --run src/recommendations.test.tsx
```

Опциональная проверка **запущенных** сервисов (оба должны обслуживать тестовый demo-v1):

```bash
cd apps/api
SEARCH_SERVICE_URL=http://127.0.0.1:8101 \
RECOMMENDATION_SERVICE_URL=http://127.0.0.1:8102 \
CATALOG_VERSION=demo-v1 go run ./cmd/roman-conformance
```

Для одного эталонного процесса укажи8101 в обоих URL. Проверка отправляет маленькую
синтетическую PNG и текстовые запросы, проверяет успешные ответы и ошибки, лимиты,
версию/ID, X-Request-ID. Каждый запрос ограничен согласованным бюджетом1с/8с.
На другую версию каталога этот fixture-набор автоматически не переносится: сначала
добавь согласованный тестовый каталог и набор примеров. Не подгоняй настоящий каталог под DEMO-ID.
Проверка запускает HTTP-вызовы по явно указанным адресам; это не нагрузочный тест.

## Где разместить на Sigma

Размещение подготовлено как соглашение, **новая служба этой задачей не устанавливается**:

- Исходники: `/srv/lct/work/<task>`, отдельная ветка. Запускаемая версия — `/srv/lct/roman/`.
- Веса/индексы/данные: `/srv/lct/data/roman/`, вне Git и web root.
- Рекомендуемые внутренние адреса: поиск `127.0.0.1:8101`, рекомендации `127.0.0.1:8102`.
  На21.09.2026 порты были свободны; перепроверь непосредственно перед запуском.
- Если один процесс — оба URL указывают на8101. Не открывай порты/служебные ручки в интернет.
- На первом серверном выпуске зарегистрируй фактические unit, пути, порты, env и откат
  в infra-os и `/srv/lct/notes/activity`; имя сервиса и ресурсы согласуй с владельцем зоны.
- На другом сервере нужен защищённый внутренний канал и аутентификация. Текущий loopback
  контракт не разрешает публично выставить незащищённый API или переслать фото внешнему провайдеру.

## Что проверить перед передачей

- Реальный HTTP: три операции, типы/лимиты, точные ID, версия каталога, ошибки JSON.
- Нет повторов/исходного вина в рекомендациях; selectedId используется только в поиске.
- Таймауты и отмена освобождают ресурсы, параллелизм ограничен самим ML-сервисом.
- Измерены задержки на названном оборудовании/входах: текст и рекомендации до1с,
  фото до8с; полный запрос приложения укладывается в9с.
- Есть modelVersion, health и диагностический request ID; запросы/фото/секреты не логируются.
- Собственный набор на независимых фото измеряет качество; зелёный контрактный тест этого не заменяет.

В ответе по задаче укажи commit, команды, вывод совместимости, версии каталога/модели,
измеренные задержки и ограничения. Не объявляй готовность по одному успешному curl.
