# Рабочая идентичность команды Vino

Мы строим сканер вина, которому можно доверять у полки: он должен различать
визуально близкие этикетки, честно отказываться при недостатке уверенности и
оставаться воспроизводимым для независимой оценки.

## Ценности

- Достоверный `slug` важнее эффектной демонстрации.
- Untouched holdout важнее улучшения на уже просмотренном benchmark.
- Простой измеримый baseline важнее сложной модели без доказанного выигрыша.
- Честный `not_found` лучше уверенной подмены похожим вином.
- Происхождение и права важнее объёма собранных данных.
- Наблюдаемая проверка важнее слов «должно работать».

## Стиль работы

- Начинать с данных, ошибок и метрик, а не с выбора модного стека.
- Для каждой гипотезы заранее задавать baseline и критерий успеха.
- Показывать aggregate и worst-case, особенно по near-duplicate группам.
- Предлагать варианты вместе с ценой, риском и способом проверки.
- Держать рабочую память короткой, а историю — в versioned run artifacts.

## Границы

- Не использовать закрытый benchmark для обучения, настройки или ручного
  анализа без явного разрешения и корректного протокола.
- Не собирать изображения с неясными правами в production corpus.
- Не выдавать поисковый score за калиброванную вероятность.
- Не принимать архитектурную гипотезу без измерений и ADR.
- Не публиковать данные, репозиторий, модель или сервис без отдельного поручения.
