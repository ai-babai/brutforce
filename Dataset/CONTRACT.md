# Контракт Dataset Vino

Версия: `1.1.0`
Дата фиксации: 2026-09-15
Назначение: некоммерческое исследование и прототипирование.

## 1. Зоны хранения

- `00_raw/<NN_source>/` — полученные байты, только чтение после приёма.
- `01_...NN_.../` — воспроизводимые производные конкретного источника.
- `90_splits/<version>/` — frozen assignment ролей.
- `91_manifests/` — safe manifests с относительными путями и хешами.
- `92_reports/` — агрегированные профили, проверки качества и leakage audit.
- `99_quarantine/` — повреждённые, неоднозначные или запрещённые к использованию
  объекты; карантин не означает удаление.

Локальные абсолютные пути, токены, cookies, закрытые URL и персональные данные в
версионируемые файлы не записываются.

## 2. Идентификаторы

| Поле | Семантика |
|---|---|
| `source_id` | стабильная версия происхождения |
| `source_capture_id` | одно событие экспорта/съёмки/загрузки |
| `media_id` | один логический медиа-объект |
| `wine_family_id` | одно вино/кюве независимо от года и редизайна |
| `product_id` | нормализованное вино как каталожная сущность |
| `bottle_variant_id` | вариант этикетки/урожая/объёма, если различим |
| `label_design_id` | визуальное поколение этикетки/упаковки |
| `slug` | проверенный slug снимка каталога, не догадка из filename |
| `identity_group_id` | изображения одного товара/варианта, запрещённые к утечке |
| `near_duplicate_group_id` | визуально близкое семейство, назначаемое до holdout |
| `parent_media_id` | исходник для crop/resize/OCR/другой производной |

Идентификатор не переиспользуется для новых байтов или другой сущности. Конфликт
`slug ↔ product_id` отправляется на ручную проверку.

## 3. Минимальная запись media manifest

```json
{
  "manifest_version": "1.0.0",
  "source_id": "caseholder-svoe-vino-2026-09",
  "source_capture_id": "capture_20260915_001",
  "media_id": "media_000001",
  "wine_family_id": "family_000001",
  "product_id": "product_000001",
  "bottle_variant_id": null,
  "label_design_id": null,
  "vintage": null,
  "slug": "wine-slug",
  "identity_group_id": "identity_000001",
  "near_duplicate_group_id": null,
  "association_grade": "gold",
  "role": "catalog_reference",
  "relative_path": "00_raw/01_svoe_vino_caseholder/example.jpg",
  "sha256": "<64 lowercase hex>",
  "bytes": 0,
  "media_type": "image/jpeg",
  "width": 0,
  "height": 0,
  "rights_status": "provided_for_case",
  "quality_status": "pending_review",
  "parent_media_id": null
}
```

Nullable product-поля допустимы до связывания, но происхождение, путь, размер и
SHA-256 обязательны для каждого принятого файла.

Один `product_id` не обязан иметь `slug` «Своё Вино». Принадлежность внешнему
каталогу хранится отдельной связью `catalog_id + external_product_id +
snapshot_id`; отсутствие exact-match в текущем каталоге не делает российское
вино бесполезным или неизвестным.

## 4. Качество связи фото ↔ вино

- `gold` — явная подпись/каталожный ID или ручная проверка этикетки.
- `silver` — однозначная связь по соседней таблице/сообщению с подтверждённым
  порядком и без конкурирующих кандидатов.
- `bronze` — эвристика по имени, времени или близости; для supervised training
  запрещена до повышения статуса.
- `rejected` — связь опровергнута.

Один Telegram-альбом или PDF не считается автоматически одной бутылкой. Связь
«фото рядом с таблицей» хранит evidence и confidence.

## 5. Очереди проверки и разметки

Каждый производный набор имеет workspace `review/` со следующими состояниями:

- `needs_verification/queue.jsonl` — нужно подтвердить происхождение,
  идентичность, винтаж, редизайн или near-duplicate group;
- `needs_annotation/queue.jsonl` — нужна полная разметка объектов/SKU/bbox;
- `verified/decisions.jsonl` — журнал подтверждённых решений;
- `rejected/decisions.jsonl` — журнал отклонённых решений с причиной.

Изображения между папками не копируются и не перемещаются: queue/decision
записи ссылаются на канонический `media_id` и `relative_path`. Правила полей и
переходов определены в `REVIEW-ANNOTATION-CONTRACT.md`. `verified` означает
пройденный review, но допуск к конкретной задаче обучения всё равно определяется
полями `training_uses` и versioned split manifest.

## 6. Роли и frozen split

В `90_splits/v1/` закрепляются:

- `catalog_reference.jsonl` — разрешённые эталоны поискового индекса;
- `train.jsonl` — допустимые обучающие query/auxiliary объекты;
- `val.jsonl` — выбор модели, preprocessing и порогов;
- `test.jsonl` — локальная финальная оценка;
- `holdout.jsonl` — редко открываемая untouched выборка;
- `caseholder_eval.jsonl` — предоставленный evaluation-контур, не для tuning.

Физическое расположение не назначает роль. `catalog_reference` может быть
доступен индексу при оценке, но его производные не становятся query training
автоматически. Один SHA-256, `parent_media_id`, `identity_group_id` или
согласованная near-duplicate family не пересекают `train`/`val`/`test`/`holdout`.
PDF с накопительными рейтингами дедуплицируется по событию, вину, винтажу и дате.

## 7. Права

Режим проекта — `noncommercial_research`. Для каждого источника отдельно
фиксируются:

- право на обучение/исследование;
- необходимость атрибуции;
- право на производные и публикацию transformed subset;
- право на перераспространение исходных изображений;
- конфликт лицензии набора и прав владельца конкретной фотографии.

`NC` совместим с текущей целью, но `ND` не исчезает. `BY` требует атрибуции,
`SA` — сохранения совместимых условий распространения. Статус
`legal_review` запрещает публикацию и обмен производными до отдельного решения.

## 8. Версии и изменения

Замена байтов, ground truth, identity или split создаёт новую semantic version.
Каждый pipeline сохраняет версию кода, входной manifest SHA-256, конфигурацию и
seed. Старый эксперимент остаётся привязан к старой версии.
