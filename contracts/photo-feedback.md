# Разметка результатов по пользовательским фото

Контур предназначен только для фотографий, загруженных через `POST /v1/photos` и
обработанных `POST /v1/search`. Текстовый поиск, рекомендации и сохранённые карточки
не создают разметку распознавания.

Успешный photo-search при настроенном `FEEDBACK_DIR` возвращает непрозрачный
`feedbackToken`. Сервер отдельно сохраняет неизменный снимок исходного результата:
фото и его SHA-256, request ID, версии каталога/модели, исходный `selectedId` и
порядок кандидатов. Клиент не передаёт эти поля обратно как доверенные данные.

`POST /v1/feedback`, `application/json`, не более 64 KiB:

```json
{
  "feedbackToken": "32 lowercase hex",
  "idempotencyKey": "32 lowercase hex",
  "decision": "confirm | correct",
  "displayedWineId": "catalog-id, omitted only when correcting a no-match",
  "correctWineId": "catalog-id, required only for correct",
  "comment": "optional, at most 2000 Unicode characters"
}
```

- `confirm` подтверждает показанную карточку и не принимает `correctWineId`.
- `correct` требует другую существующую позицию того же snapshot каталога.
- `displayedWineId` обязан входить в исходный список кандидатов. При исходном `no_match`
  он отсутствует, а пользователь может сохранить найденный вручную `correctWineId`. Ручной выбор
  кандидата хранится отдельно от исходного выбора модели.
- Повтор того же payload с тем же `idempotencyKey` возвращает прежнюю квитанцию;
  другой payload с тем же ключом получает HTTP 409.
- Комментарий хранится как данные и не интерпретируется как HTML.

Новая запись возвращает HTTP 201, идентичный повтор — 200. Запись append-only,
приватна, находится вне Git и web-root, имеет `reviewStatus=pending_review` и
`trainingEligible=false`. Она не меняет каталог, индекс, benchmark или train до
отдельной проверки происхождения, прав, identity и пересечения с held-out.
Оператор задаёт server-owned `FEEDBACK_CAMPAIGN_ID`; он сохраняется в каждой записи
и позволяет экспортировать только разметку конкретного тестового прохода.

Публичного list/export endpoint нет. Операторский экспорт читает `FEEDBACK_DIR`
офлайн и соединяет запись с приватным фото по `photoId`/`photoSha256`.

## Проверяемое поведение

- FB-001: подтверждение сохраняет одну связанную запись и показывает квитанцию.
- FB-002..004: исправление невозможно без точного SKU; выбранный SKU сохраняется,
  исходный prediction не переписывается.
- FB-005: пустой и заполненный комментарий допустимы.
- FB-006..007: одинаковый retry не дублирует запись, конфликт ключа даёт 409.
- FB-008..010: сбой не изображается успехом; подмена photo/result/SKU отклоняется.
- FB-011..013: отказ модели не становится положительной меткой; записи приватны,
  переживают restart/deploy и не включаются в обучение автоматически.
