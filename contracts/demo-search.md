# Контракт демонстрации

Это согласованный симулятор пользовательского пути, не контракт конкурсной проверки.
Производитель: apps/api (Go), потребитель: apps/web (TypeScript).
Каноническая схема успешного ответа: demo-search.schema.json.

POST /api/search: JSON с scenario exact / uncertain / none / error и необязательными query и photoId. photoId — квитанция загрузки из photo-upload.md; неизвестный ID даёт 404, некорректный — 400, недоступное хранилище — 503.
При поиске по названию query фильтрует вымышленные записи без учёта регистра.
Ответ содержит demo:true и candidates (включая пустой массив). selectedId при наличии
ссылается на одного из кандидатов. uncertain показывает выбор, exact открывает карточку.
400 — некорректный запрос, 405 — метод, 503 — демонстрационный сбой.
Ошибка: demo:true, error:{code,message}; не превращать её в пустой успешный результат.

Ограничение JSON: 64 KiB. Фото отправляется отдельно через POST /api/photos; поиск получает только photoId.
Нет настоящего каталога, confidence, OCR и измеренной точности. Две карточки синтетические.
Технические лимиты прототипа описаны в photo-upload.md; они не заявляются как конкурсные требования.

Проверки: Go httptest проверяет реальный HTTP handler без запуска порта;
UI tests проверяют компонент с подменённой сетью; отдельный smoke связывает настоящий API и UI.
При изменении схемы обновлять обе стороны и проверять их совместимость.
