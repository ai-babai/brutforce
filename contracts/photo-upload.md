# Сохранение снимка · демо v2

Разрешено Максом 19.09.2026: фото из камеры или галереи сохраняется на сервере.
Производитель: браузер; потребитель: Go API; публичного списка фотографий нет.

`POST /v1/photos`, multipart поле `photo`. JPEG/PNG/GIF/WebP/BMP/TIFF, до 10 MiB и 25 млн пикселей.
Тип определяется сервером по содержимому; после проверки заголовка и размеров декодируется изображение (GIF — только первый кадр). Максимальная сторона — 12000 px. Отклонённый файл не записывается. Разрешено ровно одно файловое поле photo, без дополнительных полей.
Это технические ограничения текущего демо, не требования конкурсного ТЗ.

201: `{id,createdAt,bytes,mime,width,height}`. id — 32 шестнадцатеричных символа.
После сохранения `/v1/search` принимает `photoId` вместе с обычным запросом.
С реальным каталогом и настроенным vision-сервисом поиск использует сохранённые
байты снимка; синтетический демо-режим остаётся отдельным.

В боевом API от 02.10.2026 только для `/v1/photos` read deadline продлевается
до 90 секунд, write deadline — до 120 секунд. Лимиты байтов, геометрии и
параллельных загрузок не меняются. Прерванная по таймауту передача возвращает
HTTP 408 `upload_timeout`: клиент может повторить то же фото; таймаут не
означает неподдерживаемый или повреждённый файл.

Данные: `UPLOAD_DIR/<id>.bin` и `<id>.json`, вне веб-корня и Git. Владелец lct,
файлы 0600, каталог 0700. Общий лимит по умолчанию 200 MiB; при заполнении —
понятная ошибка, автоматического удаления нет. Это простое файловое хранилище,
не новая СУБД. Не включать снимки в общие логи и отчёты.

При повторе после получения id использовать существующий снимок. Если клиент
отменил запрос до получения квитанции, сервер мог уже сохранить файл: повтор
может создать вторую копию. Браузерная отмена не означает удаления снимка.

Неподдерживаемые форматы (включая HEIC/HEIF) возвращают 400 `invalid_photo` и предлагают заменить на JPEG/PNG/GIF/WebP/BMP/TIFF.
Физическая камера проверяется отдельно на устройстве; быстрые тесты проверяют
запрос доступа, получение файла, остановку потока, загрузку и обработку ошибок.

Защита публичного входа: [Security Specs](../docs/product/security-spec.md). Оригиналы остаются недоверенными данными; загрузка не означает антивирусную проверку или очистку метаданных.
